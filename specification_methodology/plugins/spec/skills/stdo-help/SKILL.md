# STDO Help

Give practical help from the project's exact selected basis. This skill routes
attention; it does not replace method or Product authority.

## Select The Product Basis

Read and apply
[`PRODUCT_BASIS.md`](../../references/PRODUCT_BASIS.md) before routing or
answering. Continue into Product-specific routing only from its exactly-one
verified selection; on a stop result, return only read-only re-entry or setup
guidance. This skill remains read-only.

## Route

- Ticket creation or update: `stdo-ticket`.
- Authorized requirements, design, code, or test work: `stdo-work`.
- Independent exact-candidate evaluation: `stdo-review`.
- Product progress, monitoring, or triage help: `stdo-status`.
- Full owning-standard reload: use Claude's manual-only `refresh` where
  available, or resolve and read the exact installed member directly.

## Establish The Basis

1. Resolve the verified definition's bootstrap entrypoint and accepted Project
   Reference-Frame Basis.
   Fail closed on a missing, ambiguous, damaged, or placeholder basis.
2. Read the smallest relevant project surface: Goals, Intent, Product, affected
   requirements, accepted design, work carrier, then the owning standard.
3. If no Product Definition exists and setup is authorized, point to
   [`../../references/GETTING_STARTED.md`](../../references/GETTING_STARTED.md)
   from **New Project** without performing setup.
4. When installation is authorized, return the exact `stdo sync --definition
   <definition>` next action for a missing selected cut; do not execute it from
   this read-only skill or adopt a newer cut implicitly.

## Return

Answer directly. For re-entry, include definition identity, immutable cut and
manifest, current outcome, work carrier and re-entry point, role/grant, proof
boundary, unresolved gaps, and one next already-authorized action.

Stop when the basis cannot be reconstructed. Do not substitute mutable method
source, conversation memory, a moving selector, or a nearby Product.
