# Coordinated native skill design

This realizes [CS-01–08](../../specification/requirements/COORDINATED_SKILLS.md)
for the five native plugin skills. It adds no standard law or independent
Skills Product adoption. The implementation is an interaction projection of
the exact Product-selected method, with 3.0.3 as the conservation subject.

## One handoff procedure

`common/plugins/spec/references/COORDINATED_HANDOFF.md` holds mode selection,
packet binding, issuer preflight, recipient checks and closed return handling.
Each `SKILL.md` reaches it before its ordinary acquisition/effect path. A
receiving actor executes the same skill; the issuer does not reproduce that
skill as a bespoke brief. `PRODUCT_BASIS.md` retains basis selection and exact
member verification. Host-specific paragraphs bind available Codex and Claude
mechanisms without asserting that every host exposes a particular API.

The packet points to the existing admitted work carrier and exact control
sources. No new schema, ticket table, registry, dispatch runtime or fixed actor
count is required. If a contract already names activation entries, select the
applicable entry. Otherwise use its authorized intake; do not invent missing
authority. A required inaccessible control input prevents dependent work.

| Entrypoint | Issuing responsibility | Receiving behavior |
|---|---|---|
| stdo-work | Bind the bounded operation and its result/review boundary | Validate, construct/self-review, record and return the closed work result |
| stdo-review | Bind independent assessment and any complete slice/conjunction | Derive expectations from governing source, assess the exact subject, return technical result |
| stdo-status | Request missing observations from an actor allowed to acquire them | Read-only evidence-backed status; no implicit disposition |
| stdo-ticket | Bind the authorized creation/update and exact admission question | Writer performs only the granted carrier effects and returns evidence |
| stdo-help | Resolve a material unknown through authorized read-only assistance | Answer from the selected basis and existing rulings; no setup or mutation |

## Host and context binding

The issuer records what the selected host actually passes: task packet, inherited
history/instructions, available tool permissions, worksite and returned result.
It selects fresh context where the frame requires it. A platform that cannot
meet a required boundary returns an unsupported activation; changing a role
label cannot clear already acquired information. Host restrictions, when used,
are evidence of their specific configuration, not proof of all information
flows or review independence.

Command output is part of acquisition. A prescribed command whose output would
include excluded names or content is incompatible with the recipient frame.
The issuer selects an already-permitted bounded alternative or returns for
re-entry; recipient-side redaction cannot undo acquisition. Arbitrary command
behavior is not claimed statically decidable by a prose check.

## Qualification and distribution

Meaningful tests observe decisions and artifacts from raw fixtures, with oracle
expectations retained separately from actor prompts. Package validation checks
all reachable references, fragments, discovery metadata and preserved law.
The independent Reviewer assesses exact frozen bytes without authoring them.
Behavioral trials state model/host, supplied context, acquired support and
unavailable observations. The work return binds the resulting evidence.

The native plugin member inventory will include the added reference in the
3.0.4 release. Until that separate release operation, candidate edits do not
alter the published 3.0.3 plugin or claim published-install qualification.
