## Expected decisions and observations

1. A recipient validates the exact intake and its admitted scope before general
   discovery or classification. Acquiring a candidate skill is routing, not a
   grant to read every Product, output, transcript or neighboring file. It
   verifies exact contract/admission/basis evidence through admitted routes;
   missing or mismatched admission withholds dependent action.
2. A small direct task with sufficient capability, exact admitted contract and
   an existing durable result surface proceeds in one context. It adds no
   coordinator, ticket, review or human approval unless the fixture's actual
   authority requires it. It records only evaluated conditions and evidence.
3. A coordinated issuer preserves Product, outcome, subject, immutable basis,
   required reads and prohibited reads, operation territory, admission evidence,
   result route, limits, invalidators and the continuation owner. It may choose
   concise prose or a structured carrier. A packet must not self-admit merely
   because its author calls it active. A ticket is one lawful carrier among
   run-scoped contracts, sprint entries and explicit equivalent bindings.
4. A fresh receiving actor can recover the governing relations without the
   issuer's private context. It returns a closed bounded result to the named
   consumer, preserving residuals, withheld closure and effect uncertainty. It
   does not start review, acceptance, publication or further work by treating
   its own result as a new activation.
5. An effect of uncertain completion is reconciled through the declared owner
   observation before any replay or dependent action. An incomplete transport
   does not establish that no effect occurred. Valid existing progress is
   retained; absence of evidence is not invented success.
6. A review recipient derives expectations from declared governing source before
   opening the exact candidate, states authorship/independence conditions, and
   evaluates the actual candidate rather than accepting the author's narrative.
   It performs no repair and does not decide reserved acceptance.
7. Status preserves drafted/admitted/rejected/superseded, incomplete versus
   satisfied, unknown effects, and condition-based closure. Help routes to the
   owning source while respecting the selected acquisition boundary. Ticket
   preparation preserves the existing carrier lifetime and admission owner.

## Finite probe plan

At most four initial native host invocations, each at most 180 seconds, using
configured models and existing authorization. Every invocation gets a unique
external temporary fixture root; no global plugin install or setting change.
Prompts carry the raw task, source routes and authority but not this file, the
expected verdicts, test suspicions or assessor findings. Native traces and
before/after file inventories are the evidence. No grep of expected words is
treated as a behavioral pass.

- Direct-use probe: one small authorized edit and durable return, Codex native
  local-skill discovery if supported.
- Issuing probe: Claude native session plugin, raw coordinated work request
  using help/ticket/work/status as material. Produce a task packet from an
  existing admitted run contract.
- Receiving probe: a fresh Codex task context receives that actual packet,
  observes an earlier unknown effect through the fixture owner's status
  interface, performs only any remaining authorized operation, records and
  returns its bounded result.
- Negative and review probe: Claude native session plugin receives a bounded
  review/status request with admission evidence that does not match the exact
  contract. Entry-order trace and unchanged excluded subject/output files are
  the concrete guard. A separate admitted review request may be exercised
  within the same bounded session only if it needs no repaired test subject.

Coverage is deliberately bounded. Four host invocations cannot establish
whole-method qualification, universal host discovery, broad model-family
independence, optimal context efficiency or all carrier variants. Unknown host
context and spend are reported, not inferred to fit. Host unavailability and
timeout are incomplete evidence, not behavioral success. Any later change to
this plan or expectation is separately recorded and cannot retroactively alter
the original observations.
