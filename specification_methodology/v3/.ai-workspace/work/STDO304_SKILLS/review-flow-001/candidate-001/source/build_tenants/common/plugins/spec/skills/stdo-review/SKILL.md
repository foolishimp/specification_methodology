# STDO Review

In the execution path, act as Reviewer for one exact claim. The reviewed subject
is read-only. Record findings only through the exact artifact effects the
selected basis and activation grant. Do not repair, assign Product priority,
apply disposition, or activate the next work.

## Start With Your Own Control Intake

Read the exact own contract or intake named in the request before any general
search or project read. Bind your own permitted inputs, exclusions and return
route, then apply [Control Intake](../../references/COORDINATED_HANDOFF.md#control-intake).
This applies to issuer, recipient and direct work. Use named control routes;
do not start with directory inventories, memory searches or neighbouring
prompts. A Worker’s access never becomes its issuer’s access. Check the actual
host boundary before relying on excluded information staying unavailable.

## Choose The Entry

If receiving a coordinated packet, apply
[Receive](../../references/COORDINATED_HANDOFF.md#receive) before general
discovery or candidate reads, then execute the review below within its grant.

A coordinating issuer uses [Issue](../../references/COORDINATED_HANDOFF.md#issue)
with `EXECUTIVE_BASELINE` §12 step 5B and §19's Reviewer additions. Bind the
exact claim, candidate, evidence population, severity scale and required
authorship/evidence independence. Let the Reviewer derive expectations from
governing source before candidate exposure (`EVALUATION` §3). Label supplied
hypotheses or counterexamples as inputs; they neither prescribe the verdict
nor replace independent assessment. Do not hide relevant evidence to create
an appearance of independence.

Partition only when each Reviewer has a sufficient complete slice and the
declared conjunction covers the required claim, including interactions.
Local green slices do not prove an unassessed whole path. Evaluate returned
results through [the shared return procedure](../../references/COORDINATED_HANDOFF.md#evaluate-the-return);
retain Reviewer severity and assign priority/disposition only under the
issuer's separate grant. The issuer does not perform a second review merely
by issuing this one. Apply [the selected review flow](../../references/COORDINATED_HANDOFF.md#review-flow-from-the-selected-basis)
for coverage, proportional sizing and any recheck; do not copy the optional
candidate policy onto an older basis. Otherwise enter the Reviewer path below.

## Select The Product Basis

Read and apply
[`PRODUCT_BASIS.md`](../../references/PRODUCT_BASIS.md) before activating review.
Continue only from its exactly-one verified selection. That selection supplies
no artifact-write grant.

## Activate The Review

1. From the verified definition and installed basis, bind candidate/checkpoint,
   exact affected Product claims, authority, scope,
   exclusions, evidence population, required independence, Reviewer capability
   envelope, Executive baseline profile technical-triage fields where adopted, the
   Product-selected severity scale, review time, and invalidation under the
   three invalidators of `ACTIVATION.md` section 7, a subject, capability or
   scale change being a named instance of a material input change or a
   changed basis.
2. Reacquire live authority, implementation, tests, fixtures, installed or
   runtime evidence, and material history. Do not use the Worker summary as
   evidence. Acquire owning sections under the selected basis's
   `ACTIVATION.md` section 2, Acquisition; review law is `EVALUATION.md`
   sections 3 and 4.
   Reuse exact applicable computed facts and traceable prior judgments after
   checking their support and invalidation. This does not replace your own
   assessment where the claim requires independence. Determine required
   evaluations from the owning applicability conditions, not only the caller's
   selected frame list; unknown applicability or a missing required exact
   result prevents a satisfied conjunction.
3. Return the exact invalid, out-of-frame, or indeterminate result when subject,
   basis, capability, independence, or evidence cannot support evaluation.

## Evaluate

- Search for counterexamples against the claim: authority seams, rival paths,
  proof masking, failure/recovery, installed behavior, and reconstruction.
- Inspect tests, fixtures, mutations, environment, and interpretation where
  they can change the proof.
- Bind findings and affected acceptance predicates to a violated property,
  supported entry/state, governing operating/threat model and credible causal
  path. An excluded threat gives no guard a retention claim; test presence
  creates no authority (FOUNDATIONS §2 What creates no authority). Internal location alone does not establish trust.
  Preserve supported input, mutable-state, authority and effect checks.
- For material computational composition or recurrence, evaluate one complete
  producer-to-consumer path, including established facts, invalidators, effects,
  retained alternatives and accumulated work. Require the claimed operational
  observations; local passes or semantic agreement cannot establish them.
  Reuse still-valid support without substituting another actor's judgment for
  the required independent assessment.
- Under an adopted Executive baseline profile, return technical severity, causal
  assessment and confidence where supportable, blast radius, workaround or
  containment, repair complexity, regression risk, and residual uncertainty.
- Use only the Product-bound scale. Keep adjacent observations separate.
- Never turn technical severity into Executive priority or promotion-boundary
  effect. Whether a finding blocks promotion is decided by EVALUATION §5 When
  a finding blocks promotion.
- Distinguish repair of a nonconforming candidate under unchanged law from an
  intentional governing change. A failure alone does not require repricing.
- Check satisfied closure conditions; your review event cannot establish them
  or create an additional closing ceremony.

Keep the result projection total over the core values of `FOUNDATIONS.md`
section 4, Results:

- `satisfied`: no finding; triage is `not_applicable`;
- `falsified`: findings carry complete triage or explicit field-level
  indeterminate values;
- `indeterminate` or `out_of_frame`: return the unresolved triage and basis;
  and
- `invalid_basis`: triage is `not_applicable`; return the basis re-entry.

## Return

Return one closed result containing exact subject and basis, claim, scope and
exclusions, evidence, verdict, findings and counterexamples, triage, residuals,
adjacent observations, uncertainty, invalidation, and owning re-entry point.
Bind each reusable judgment to its question, subject/basis, supporting facts,
actor/authority, conclusion/scope and revising observation in the existing
result carrier. Preserve original owner rulings separately from interpretation.
Name any unperformed coverage. When the selected TICKETS law provides a linked
bug report, record it only at the exact granted identity/path, with unchanged
severity and inherited visibility restrictions; otherwise return it for the
lawful Writer. With no findings, create no bug report. Return the report link
without exposing withheld evidence in the surrounding summary.
Return to the coordination the applicable configuration selects: the
Executive when the Project Reference-Frame Basis adopts that frame;
otherwise the Product-owned decision authority. Stop.
