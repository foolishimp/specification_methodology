# STDO 3.0.4

A normal standalone release, continuing 3.0.3. This publishes the owner's
accepted scope with the recorded qualification limits; no further RC/final
cut is needed. Existing consumer bases remain unchanged.

- Five native skills—work, review, status, ticket and help—share bounded
  issuing, receiving and return paths while preserving direct work.
- Review distinguishes landing, work closure and Product release. Severity
  is graded 1 highest to 5 lowest, separately from Executive priority.
  Severity 3 gets an explicit downstream-impact assessment: material dependent
  impact normally calls for repair; contained deferral needs a reason and owner.
- The source reader fixes Unicode line/fence boundaries and empty ATX headings,
  preserving exact physical lines and refusing unsupported Markdown structures.

```sh

stdo verify v3.0.4 --manifest-sha256 102817a3f4bea4dca1d6fa0fc634b94404dd2ba82ba6d8c38b273402dda9f95b
stdo resolve stdo://releases/v3.0.4/standards/documentation/index.html
```

The four assets supply manager 0.1.6, the exact manifest and both checksums.
The guide includes fresh-machine bootstrap. Documentation retains the offline
3D/2D/Layered constraint explorer, ABI code example and Lean proof reader.
These representations/proof results remain historical, not a complete graph
or fresh proof of all 3.0.4 law. Optional execution dependencies are installed
only into an explicit writable tooling workspace.

The source and bounded release checks pass. Native workflow evidence remains
mixed: two strict-return failures, a separately verified R1 recovery, R2's
conditional record and E1's unsupported authorization/grouping claim; no
execution followed that claim and no successor actor trial ran. Other modes,
full independent-review operation and broad host portability remain
unqualified. Publication does not convert those limits into passes.
