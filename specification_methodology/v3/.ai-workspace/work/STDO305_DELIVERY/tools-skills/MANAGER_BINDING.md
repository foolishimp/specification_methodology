# Explicit selected manager/store binding

Root accepted the common setup owner's anchor-local manager launcher as the executable-only consumer route for an explicitly selected store. The launcher pins its underlying manager, actual store and native manifest; it invokes the manager with an explicit `--store` argument and refuses caller override. This is a runtime installation anchor, not a nominated Product adoption.

The Skills installer will preserve its selected manager invocation spelling, pin the physical executable bytes, and retain the verified manager result's `runtime_launcher` object. CONFIG.manager_identity will have `invocation`, `physical_path`, `sha256`, and `runtime_launcher` (the exact seven-field launcher object, or null for a direct manager). Before a later check-runtime invocation it will recheck all selected executable/manifest bytes and the real store. The fresh returned launcher object must equal that retained selection. This adds no ambient-store fallback or rewriting of a nominated Product. Both host routes will exercise the actual common generated launcher with the environment unset/wrong, plus stale launcher, underlying manager, store and manifest controls. Installed nativeA remains a separate qualification step.
