# Current model construction and view relation

This design realizes REQ-P-CURRENT-MODEL for the owner-selected 3.0.5 cohort.
The old a_c prototype and the old Axiom-only program remain historical inputs.
Neither is silently adopted as current representation.

## Public flow

1. Verify semantic freeze S and copy its exact members into the Representation
   tenant's immutable source snapshot. Preserve the complete inventory and
   source URI mapping; include generated frames as routes with owner checks.
2. Freeze this Product Definition and invoke the pinned `ac_project.py`
   `prepare` in direct mode over explicit snapshot sources. The released 3.0.4
   provider's 19-task attempt and explicit-envelope refusal are retained. The
   owner-authorized current 3.0.5 provider extends the explicit finite cap to
   3,000,000 characters, preserving defaults and complete validation. Its exact
   29-file pin set binds the actual succeeding public run. Direct mode uses
   no optional Graphify installation and claims no Graphify trial.
3. Obtain every public task; author through bounded source/dependency cones.
   Retain a per-record conservation ledger for grounded unchanged meaning,
   fresh answers for affected meanings, and coverage dispositions for all
   selected sections. Public submit validates grounds, keys and dispositions.
   One public transaction preserves cross-section concept identities; bounded
   LLM acquisition remains by owner/dependency cone. Transaction size is not a
   measured context size or efficiency claim.
4. Public build emits the single model/carrier/coverage and source-linked
   explorer. No selected formal checker is implied; the formal owner consumes
   the exact model separately and records actual Lean evidence.
5. Exact Axiom 3.0.5 mechanics convert the model with caller-declared source and
   frame bindings, then validate/map/project. Conversion retains a reversible
   encoding of declared record and model metadata while exposing the same
   semantic statements and references as bounded native index entries.
6. Preserve exact model equality on reverse conversion, original reference
   closure and source grounding. Native views may omit content only under a
   declared projection whose source identity remains recoverable.
7. Release tools package selected current viewers/model/proofs; external final
   cohort binding closes the final native manifest without making it an input
   to embedded semantic records.

The five current Axiom indexes take the provider's actual required closures
for native work/control intake, common F_D, Product composition, finding
reports and source-closed release. They bind the source-owned Worker or Reviewer
frame and a narrow declared scope. Exact closure membership is checked in both
Axiom modes against those a_c selections; this is not a claim that every possible
selection or all methodological dependencies are equivalent.

## Invariants and failure boundaries

- One canonical model; the Axiom program and all views are derived artifacts.
- No source path, hash, label or lexical match creates meaning or authority.
- Reuse requires unchanged governing semantics as well as exact grounds.
  Changed authority, F_D, edge, review and release clauses re-enter their
  dependency cone even when some sentence bytes remain unchanged.
- Conversion is generic provider work. STDO-specific frame selection and
  semantic judgments stay here; a generic converter cannot invent frame law.
- Missing source, partial authoring, failed preservation or stale source/map
  refuses the affected build or view. Diagnostics do not become acceptance.
- Host author identity is declared; no fresh isolated-agent or provider
  attestation claim is made for ordinary public submissions.

## Evaluation

Compare exact source inventory and all grounds; verify public task/submission
closure; verify model/carrier checks and conversion round-trip equality;
reproduce the logical map and both projection modes; exercise malformed,
dangling, stale and wrong-source refusals. Independent semantic/native review
uses source-derived expectations and actual task evidence. The Executive owns
that allocation and the final release disposition.
