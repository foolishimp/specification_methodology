# Claude base, Codex donor: STDO V3 successor plan

Use Claude RC9 as the structural base and Codex RC9 as a selective donor. Preserve Claude's entities, ownership boundaries and result semantics; translate each demonstrated Codex improvement into the existing owner. This is the stronger synthesis strategy under the owner's stated preference for structure over compression. It does not establish that either RC9 is qualified for release.

**This return is the donor plan. No candidate edits have been applied.** The owner described a direction to take Claude as the base and walk every feature for donor value; a plan-versus-immediate-implementation clarification was sent asynchronously and had not been answered when this plan was written. Candidate source, prior reviews and release standing are preserved. The current result makes the proposed changes concrete before construction.

A **base** is the frozen architecture and semantics carried into the successor. A **donor** is a frozen comparison source whose useful contributions can be adapted; it supplies no competing authority. A **feature** here is an owned capability with its entities, predicates, consumers and evidence, rather than a file or paragraph. An **adaptation** preserves a donor benefit while expressing it through the base's owner and semantics. A **successor candidate** is the resulting new subject: inherited evidence applies only where its dependencies and scope still hold.

**Selection rule.** Include a donor contribution only when it preserves a useful distinction, closes a demonstrated defect, makes an existing obligation reliably available at its point of use, or supplies a stronger validation mechanism. Similar wording elsewhere is evidence of overlap, not automatically a missing feature. Smaller bytes or fewer files do not by themselves establish value. An equivalent feature receives an explicit retain decision; a different predicate or result meaning receives a separate semantic decision.

**World Model is a targeted improvement, with its entities preserved.** An entity is recovered from the domain's function, interactions and supporting evidence, then expressed in the profile's eight-surface cut. It is not invented merely by declaring a type. A Markov object is the profile's proposed stable, self-bounding pattern whose internal state can be reasoned about through an effective blanket, currently characterized as an identity-preserving projection. Its promotion gate asks whether, given that identity projection, residual variation is independent of the target under plausible treatments. The reported tests did not meet that predicate, so the construct and its overlays retain candidate standing. Ordinary lawful entity cuts do not acquire a new mandatory Markov-proof requirement from this plan. Preserve Claude's domain-result table and distinction between failed, unknown and unperformed evaluations.

Borrow Codex's four clearer applications: current observations can invalidate present reliance on an immutable historical cut; predictive adequacy and achieved construction outcome are different assurance claims; asserted absence/non-applicability requires evidence while unexamined material remains unresolved; append-only history is an added profile policy rather than a necessary deduction from facts or identity. The last change retains the policy obligation while correcting its stated grounds and recording the affected disposition. Relevant sources: Claude WORLD_MODEL lines 178, 379–509, 804–859 and 1164–1246; Codex WORLD_MODEL_METHOD lines 38, 496–501, 808–833 and 1102–1111, all pinned in F21.

**Incompatible imports to exclude from direct transfer.** Defining the entities and evaluated predicates first avoids manufacturing contradictions by copying similarly named records.

- **Core result/performance record.** Claude gives an unperformed evaluation no core result. Codex's record has a performance coordinate and can preserve an independently supported verdict when evaluation performance is nonperformed/unconfirmed. Keep Claude's meaning and translate examples into it. Copying the record or adding donor Judgment fields would be a semantic/signature change with consumers to rebind. See F3 and F9.
- **ODD closure decision.** Claude's explicit mapping evaluates edge fitness, with acceptance disposition distinct. Codex separately evaluates whether issuance of a decision was lawful: a lawful repair decision can coexist with a failed edge. This is a potentially useful distinction, but copying its verdict map would change the question being answered. Retain Claude's map in this successor plan; record a separate proposal only if the owner wants both predicates made explicit. It does not block the compatible ODD improvements. See F18.
- **Project binding and change maps.** Known zero/multiple bindings can falsify a uniqueness claim while a dependent operation is out of frame or indeterminate; these are different evaluations. Likewise, Claude's changed/unchanged/covered facts are not the donor's determination predicates. Keep base maps and use donor examples only where their predicate is named. See F11–F13.
- **Foundational and profile structure.** Keep Claude's ontology, P0–P6 commitments, F1–F22 family index, PROFILES boundary, dedicated binding owner and result algebra. Do not transplant Codex's F1–F6 commitment names, distribute the base owners, add a mandatory TRANSFORMATION_LIBRARY, or replace whole workflow files. Optional profile availability does not imply adoption. See S1, S2 and S12.
