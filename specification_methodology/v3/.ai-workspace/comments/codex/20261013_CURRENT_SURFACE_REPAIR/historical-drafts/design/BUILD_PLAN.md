Status: tenant HOW proposal, derived from the accepted [C1](PRINCIPLES.md) and
the proposed [C2 capabilities](C2_CAPABILITIES.md). Jim selects the common C2
capabilities, audience and acceptance contract before actual-use steel threads.
The plan builds documents; it creates no workflow runtime and makes no release
or adoption claim. Tenant work stays on its own branch and in its own territory
under [Development Isolation](../../../specification/PRODUCT.md#development-isolation).

## Library Before Instances

Use one definition of each shared transformation family. An instance binds a
purpose, subject, basis, required relations, responsibility and permitted effects.
Different instances do not require different mechanisms merely because their
names, inputs or owner roles differ. A new primitive is justified only by a
material semantic, authority, effect or failure distinction that the existing
definitions cannot express without losing the outer contract.

| Shared family | Performed relation | Preserved distinctions |
|---|---|---|
| Bind | Recover the exact current work subject, governing contract, role and live authority. | Purpose, identity, state, evidence and permission. |
| Acquire | Obtain sufficient material context or return unsupported acquisition/fit. | Source owner, exact selector, authenticity, availability, completeness and coupled invariants. |
| Transform | Produce bounded output/effects inside an admitted contract. | Original input/producer, actual effects, output and unresolved conditions. |
| Evaluate | Judge an exact predicate using sufficient admissible evidence. | Candidate, observation, judgment, assessor and required independence. |
| Conjoin | Combine compatible applicable results without losing failures or coverage. | Original citations, known failures, uncovered requirements, incompatible basis and uncertainty. |
| Dispose | Select the next already-authorized action from current state and result pressure. | Evaluation versus decision, repair owner, continuation, yield, stop and exhausted authority. |

These are proposed library relations, not new runtime APIs or universal required
serialized records. Bind/acquire/evaluate can involve I/O in a computational
realization; informational contracts do not make those operations cost-free.
Internal probabilistic solution strategy remains the worker's HOW. Pure helpers
can be shared without combining semantic owners or independent assessments.

Retain U (purpose), O (object/current state), κ (interpretation context), Σ
(common WHAT), algorithmic descriptions, informational interpretations and
computational realizations over architecture H as simultaneous views. They are
not sequential development phases. Publish only the supported categorical
fragment from C1; broader equivalence, hardware metrics, statistical Markov
structure and HoG monadic binding remain separately scoped research claims.

## Proposed Canonical Document Owners

Document names and grouping are Codex HOW. Common acceptance depends on behavior,
not these filenames. The first thread creates only its necessary clauses and
source routes. Later threads extend the same owners rather than starting another
parallel rule set for each observation.

| Planned tenant document | Owns | Imports instead of duplicating |
|---|---|---|
| standards/FOUNDATIONS.md | Interpretation, purpose, scoped objects, supported algebraic accounts and explicit open hypotheses. | Accepted C1 arguments and exact recovered source. |
| standards/SPEC_METHOD.md | Intent/Product/common WHAT/HOW derivation, realization boundaries and composition obligations. | Foundations; domain-specific design profile; work/evidence contracts. |
| standards/WORK_METHOD.md | Bound activation, sufficient context, execution/effect observation, current-state continuation and next-action disposition. | Evidence result algebra and governing WHAT/authority. |
| standards/EVIDENCE_METHOD.md | Claim/evidence/assessment boundaries, authentication, applicable independence and truthful conjunction. | Scoped identity/basis; qualification acceptance contract. |
| standards/QUALIFICATION_METHOD.md | Claim-appropriate actual-use evidence, operational claims, dependency, successor and release/adoption boundaries. | Work and evidence meanings; separately owned a_c mechanics. |
| standards/profiles/ | Optional software design, graph execution, work records and world-model contracts. | Core obligations; each profile's domain-owned meaning. |

Ticketing is a work-record realization when selected, not a prerequisite to every
direct bounded action. Graph traversal supplies a computational realization;
a graph's admitted validation can be reused on the same predicate and basis while
dynamic input/binding admission stays current. Operational state and evidence
ownership are selected by the profile; recovery does not require all history in
working memory. A deployment/UAT fixture is a test subject, never a core feature.

A published entry and responsibility views route a reader to these owners. A view
may be a sufficient projection for its declared claim; it cannot become rival
authority. RF-017 overlap stays when it supplies independent evaluation or a
different necessary evidence/capability altitude. UP-014 contracts duplicated
meaning and needless reconciliation, not every repeated explanation.

Thread grouping is an implementation plan, not universal lifecycle stages. An
already-supported equivalent proof may be reused on unchanged applicable relations;
a new candidate, basis or material dependency reopens only affected claims.

## Worker Scaffold

Each selected activation recovers the outer outcome, exact subject/preimage,
governing source and sufficient material relations; then binds its capability,
permitted effects, exit condition and truthful stops. Use the existing durable
work/return carrier rather than another control-pack hierarchy. These facts can
be expressed in different lawful HOWs; their headings are not a new required form.

| Responsibility | Bounded work and return |
|---|---|
| Writer | Construct only selected own-tenant clauses/fixtures. Return exact frozen output, observed effects, author checks and unresolved obligations. Preserve accepted C1 bytes and historical reviews. |
| Source evaluator | Recover a named deciding source relation; return its standing, implications and limits. It changes no candidate or authority. |
| Independent assessor | Recover source and expectations before reading the named frozen output. Judge actual material; retain failures/citations and evidence limits. Repair and acceptance remain outside its grant. |
| Executive | Consume closed returns, triangulate a failure and select only an already-authorized next action. Filesystem and Git effects require a separate Writer activation. |
| Common owner/pen | Jim selects common scope and acceptance; the pen authors it on main. Tenants import accepted changes inward and request shared repairs rather than patching common files. |

A failure stops the affected promotion before retry. Triangulate Product meaning,
design, producer/consumer join, identity/basis, authority/effects and proof. Do
the smallest supported owning repair or request governing re-entry; an unresolved
cause stays unresolved. Repeated unchanged failed actions cannot count as progress.
No fixed reviewer population, additional ticket taxonomy or actor topology follows.
Cross-tenant review remains Jim-authorized, named-commit and reviewer-owned.

## Measurement And Completion

Measure progress by closed selected claims and useful proved joins, not document,
receipt or event counts. Report current output, assessment, residuals and next
permitted action in one own-tenant return per bounded increment. Earlier returns
and accepted source retain their historical subjects; do not rewrite them green.

For selected operational claims record the envelope, material preparation/context
transfer and external work, memory where relevant, elapsed time and observed
provider counters with their original semantics. Compare the same adequate
outcome and include displaced assurance/human costs. Neither raw line count nor
a shorter prompt proves proportionality. No global budget or instrumentation
system is required by this document.

Completion requires the selected common obligations on the exact candidate,
sufficient practical and semantic evidence, resolved material contradictions and
Jim's acceptance within its declared interval. Complete successor, release and
adoption require their separately selected relation and authority.
