## Confirmed Findings

### R1 — P2: The generic construction chain still requires software and event sourcing

Claude `standards/SPEC_METHOD.md:192–221` defines the constitutional chain through **Code → Events → Projection**, says projection reconstructs current truth from the event stream, and makes every link load-bearing. The same member at `1705–1708` applies build-tenant binding to every product and at `1754–1768` explicitly permits a human process. The surrounding owners supply no scope restriction or translation that makes code and event-stream reconstruction optional for that case.

Counterexample: a wholly human approval process has an authoritative current record, retained evidence sufficient for its obligations, permitted human operations and an observation-based recovery procedure. The binding rule permits it; the universal chain demands additional software and event-history machinery. The actor has to invent an exception or add an unsupported prerequisite.

Root cause: the broadened realisation contract has not propagated to a deciding consumer inherited from the software-specific predecessor. This falsifies the affected member's criterion 5; other missing assessments remain separately unresolved.

Codex handles this case explicitly at `successor/standards/SPEC_METHOD.md:1113–1119`: realisation includes a performed human procedure, events are a selected carrier, and projection need not replay a complete event stream. This is a concrete source advantage on the same case, not a claim about every Codex path.

Bounded repair: make the generic chain consume the existing realisation/observation owners and retain code/event-stream requirements only where their profile or execution binding selects them. Recheck its projections and consumers. [Source review](20261015T160637Z_REVIEW_CLAUDE_I4_COMPARISON.assets/source-review.md) and [matched-path review](20261015T160637Z_REVIEW_CLAUDE_I4_COMPARISON.assets/path-comparison.md) independently identify the same defect; it is counted once.

### R3 — P2: The proposed trial can remove a required check after the control succeeds

Claude `qualification/C3-ITER4/trial/DESIGN.md:52,65–66,121–127` defines `M` as method-decided and `F` as fixture-stated. Criterion 4 is judged only on `M`; any `M` item a control run passes is reclassified as `F`.

A control's correct answer does not establish that the fixture states the answer. The control may infer it. If the control answers correctly while the frame misdirects its actor, the reclassification removes the still-applicable failed item from criterion-4 assessment. The distinction between causal benefit and correct use has been lost.

This is a prospective grading/coverage defect, not an observed failed trial. At the reviewed snapshot the trial is preparing expectations and has no completed actor results. Codex has no I4 actual-use campaign either; this finding gives it no demonstrated usability advantage.

Bounded repair: retain every applicable required task judgment for criterion 4. Use control outcomes separately when assessing what benefit can be attributed to the method. The path reviewer confirmed this parent-supplied counterexample and discloses that provenance in its [report](20261015T160637Z_REVIEW_CLAUDE_I4_COMPARISON.assets/path-comparison.md).
