## 3. Four-way diagnosis and layer-based re-entry are compatible

**Disposition: reject the claimed shared routing failure on the supplied cases.** The two-way wording is compressed, but the acquired procedures retain the prior diagnostic result and the actual owner's re-entry route.

Both generic gap procedures begin with intake triage and end by requiring the lawful change class selected there (`C:SPEC_METHOD.md:3394-3407`; `L:SPEC_METHOD.md:1157-1168`). Intake distinguishes realization, governing requirement/design, prediction and observation, preserves unresolved alternatives, and can select additional observation before repair (`C:SPEC_METHOD.md:1414-1450`; `L:SPEC_METHOD.md:836-864`). The change classes classify the affected owner/layer, rather than repeating diagnostic-cause names (`C:SPEC_METHOD.md:1458-1468`; `L:SPEC_METHOD.md:866-888`). These are separate dimensions.

| Supported diagnosis | Existing lawful route |
|---|---|
| A predictive model's implementation or fitted parameters are wrong while the governing requirement and design remain adequate | Correct its realized surface under the admitted local/refactor route; if the model's structure must change, re-enter its design owner. If the governing required meaning must change, re-enter that owner instead. |
| Available observations cannot decide the obligation | Acquire the missing evidence under the existing bounded grant before selecting a repair. If a defective instrument or observation procedure is established, route its correction to its realized or design owner. |
| A test oracle implements a justified expectation incorrectly | Correct the checker/test realization under unchanged upstream authority. If its expected predicate itself misstates or exposes an inadequate governing obligation, follow that source's owner and change class. |

An incorrect oracle is not automatically the same diagnosis as insufficient observation: observations can be adequate while the checker or assertion interpretation is wrong. The common law requires causal distinctions and owner routing, not an `observation_repair` enum or a new delivery carrier.

The computed-treatment consumers reinforce this reading: repair the candidate when the current contract is sufficient; change governing meaning only when the admitted outcome or evidence requires it (`C:SPEC_METHOD.md:1592-1605`; `L:SPEC_METHOD.md:967-991`). No acquired rule requires changing Z merely because a prediction was inaccurate or evidence was unavailable. The cross-family report therefore does not establish the mandatory shared repair on which its recommendation was conditioned. An actual example where a known governing owner cannot be reached would reopen this judgment.

## 4. Codex does not fabricate performance in the examined missing-check paths

A view that discards performance where material would violate `C:FOUNDATIONS.md:388-390`. The possibility that someone could write such a view is not evidence that a permitted view or actual consumer does so. The cross-family report supplies no offending projection; the sampled consumers carry the required distinction. Claude's absence-of-result representation is a reasonable design alternative, not proof that Codex's richer record is inconsistent.
