# Ordinary Entry Trial With a Bound Fixture

This is a successor of [the original protocol](../PROTOCOL.md). Its three
original observations remain unchanged. The rc.2 actor stopped because the
STDO construction Product Definition did not bind the disposable `workspace/`.
The original candidate actor proceeded only to unapplied candidates while
recording that same unresolved relation. Those runs do not establish matched
construction effectiveness.

This fixture has its own Product Definition. Its WHAT is the original D1 task;
its HOW contains the original D1 workspace. Its definition selects the authentic
installed rc.2 builder. The host runs the real `stdo status --definition ...
--verify` for each temporary fixture root and preserves the receipt. The
definition represents a qualification test subject, not a released product,
new method, new STDO installation or user application. It is never registered
or published.

The task, oracle, original four files, native model, tool set and per-call
limits are unchanged. The fixture's project frame basis binds the ordinary
installed baseline to the subject and the already-authorised proposal grant;
it supplies no selected task frame, oracle answers or repair directions.
The ordinary skill still chooses which task-specific material to acquire.

The Executive selects the new frozen candidate cut before paid execution.
Candidate and rc.2 calls start from separate copies of the same admitted
fixture. If the first candidate returns proposals satisfying the unchanged
oracle, the host persists only its valid `deploy/env.example` proposal and
actual return. A fresh third actor continues that actual partial state without
private history. This remains a deliberate partial host application, not a
provider crash. Failed candidates are retained and triangulated before any
further dependent work.

At most three new calls and USD 6 are reserved by the separate repair grant.
Each call retains the 120,000 selected-byte allowance, 15-minute wall allowance
and USD 2 ceiling. The original protocol's measurement exclusions and acceptance
limits still apply. All source, fixture and prompt changes are recorded here;
the previous raw observations are not overwritten or regraded as successes.
