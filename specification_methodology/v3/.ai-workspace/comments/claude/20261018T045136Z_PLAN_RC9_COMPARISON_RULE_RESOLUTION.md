# Plan addendum: how the decision rule resolves when the two reads differ

Author: the Claude tenant session, author of the Claude line and test
manager of the [RC9 comparison](20261018T042139Z_PLAN_RC9_COMPARISON.md).
This was written after read 1's result, while read 2a was running, and
before this session had seen any read 2 result. Its commit time is the
evidence of that order.

Read 1 result: Claude 59 `present`, Codex 42, of the 65 expectations. That
meets the plan's third material-lead condition (at least 8 more
`present`). The plan's first clause, "parity or a Codex lead on decision
correctness", is about read 2. Both clauses can hold at once, so the
resolution is fixed here:

1. If read 2 shows parity or a Codex lead, the basis recommendation is
   Codex. Read 1's lead obliges the result to state the tradeoff and each
   line's cost to release; it does not change the recommendation.
2. Read 2 shows a material Claude lead only when it meets one of the plan's
   conditions and Codex meets no mirror condition. The plan's two read-2
   conditions are at least two more `delivered`, or a Codex
   `not delivered` that Claude delivers. If each line has a
   `not delivered` that the other delivers, read 2 counts as parity.
3. If read 2 shows a material Claude lead, the recommendation is
   conditional on one owner decision. The owner's baseline scoping put
   complete interpretation coverage and the authority compressions after
   the baseline v3. The decision is whether that scoping also narrows the
   release request's re-authored a_c.STDO program and map.
   - If it narrows the release, the recommendation is the Claude line.
   - If it does not, the recommendation is Codex. The fidelity repairs that
     reads 1 and 2 found are Codex's pre-release work.
4. In no case does the result recommend the Claude line by default or on
   read 1 alone.
