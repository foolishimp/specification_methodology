### M1. An unauthorised mutation is an actual effect (row 67)

- **Source:** Codex TRAVERSAL_OCCURRENCE_PROFILE.md 1150–1152 ("evidence
  that no mutation began") and 1182–1184 ("An unauthorized mutation is
  still an actual effect").
- **Receiving owners:**
  - Claude ACTIVATION §3 Effects (1122–1175) holds the general rule;
  - TRAVERSAL_OCCURRENCE Mutable-subject effect relation (1348–1349, table
    row 1373) holds the profile's evidence condition.
- **Adaptation:**
  - ACTIVATION §3 Effects gains one sentence. An effect on the subject that
    no grant authorised is an actual effect. It is reconciled under §5
    before any dependent action. A refusal of authority never establishes
    that no effect occurred.
  - `refused_effect` requires evidence that no mutation began, authorised
    or not.
- **Gap:** Claude's `refused_effect` needs only evidence "that no authorised
  mutation began" (1349) and maps to `not_effected` (1373). So a refused
  attempt during which an unauthorised write began can be recorded as
  having effected nothing, and repeated. Common basis:
  - common README 168: an effect of unknown completion never maps to no
    effect;
  - common README 97: unknown effects are resolved before the next
    dependent action.
- **Meaning:** changes one evidence condition and adds a rule. 1 row.
- **Frame bytes:** ACTIVATION §3 Effects is copied into `binding`,
  `configuration`, `stale-summary` and `traversal-task-f`: about +250 B
  each.
- **Check again:** the Effects table keeps its three values; the S2 trace
  (an unknown external write).
- **Depends on:** M2, whose outcome Msg family maps onto the Effects values
  this loan amends; ACTIVATION §5, which reconciles uncertain effects.
