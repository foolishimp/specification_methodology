# Current development tools

The current source arrangement has separate owners for method, purpose context,
host skills and visual documentation. See the repository
[development inventory](../../../DEVELOPMENT.md).

- [Purpose Context](../../../purpose_context/README.md) owns the public context
  runtime, reusable indexes and PUBLIC_MANIFEST.json.
- [STDO Skills](../../../stdo_skills/README.md) consumes that exact Product through
  its independently inventoried package and optional visual dependency. Start with
  its [installation guide](../../../stdo_skills/scripts/INSTALLATION.md), then
  [Getting Started](../../../stdo_skills/GETTING_STARTED.md).
- [Representation Tools](../../../a_c/README.md) owns the separately inventoried
  visual runtime. STDO Representation and Axiom Indexer provide their declared
  visual documentation/conversion capabilities.
- [STDO 3.0.4 binding](STDO_3_0_4.md) still selects the exact installed native method
  and workflow. Current source adds the [SDLC default](../build_tenants/common/standards/SDLC_DEFAULTS.md),
  [examples](../build_tenants/common/standards/examples/SDLC_DEFAULTS.md), a
  [frame-template selection](../build_tenants/common/standards/templates/PROJECT_REFERENCE_FRAME_BASIS_TEMPLATE.md#sdlc-default-selection)
  and native work/review guidance. The [3.1 release relation](../specification/requirements/RELEASE_3_1.md)
  selects their successor publication; the installed construction payload and
  existing consumer bases remain unchanged.

For this source Product, follow its [explicit default selection](../specification/REFERENCE_FRAME_BASIS.md#selected-sdlc-default):
bind the outcome and claim, construct and do incremental QA, diagnose the cause,
re-enter its owner, verify affected claims, and continue or close within the
grant. Ordinary mechanically decidable repairs may close on the required tests;
the selected independent recheck triggers and named Product/release boundaries
retain their own conditions. The guide introduces no numeric policy or new gate.

Purpose Context exposes two distinct useful purposes: `sdlc-workflow/1` for
workflow decisions and `python-pure-refactor/2` for its narrower construction
constraints. The release cohort binds their applicable indexes to the actual
final native 3.1.0-rc.1 cut and manifest. Preserved development/earlier-release
entries retain their original standing. Match the caller's actual source,
purpose, scope and adoption; do not use a Product's 3.0.4 construction basis as a
substitute for the index's semantic target.

Install Skills from its independently selected distribution with the actual
native method root and pinned Purpose Context root. Its returned receipt owns
verification/removal; its `stdo-context` provider returns the canonical Product
skill and public pin. Follow those returned paths to bind, select, consume and
check an actual query. A supported exact-query assessment or an existing
authorized trial has its declared standing; no example query supplies authority
or transfers coverage. The [native first-use guide](../build_tenants/common/plugins/spec/references/GETTING_STARTED.md)
connects that context to work, review and Product disposition.

The root [3.1 activation](../../../.ai-workspace/work/STDO_3_1_RELEASE_2026-11-15/ACTIVATION.md)
owns current cohort construction, qualification and publication. Current context
use does not require a visual representation or Lean installation.

receipts retain their original coordinates and hashes. Use the original exact
release/source tree when reproducing those operations; relocation alone does not
rebind their dependencies to current Products. Released ZIPs, native payloads,
installed packages and their method law remain unchanged. Historical tooling
and generated proof/documentation remain in exact `stdo://releases/v3.0.5-rc.1/`
and preserved source. The current native [reading guide](../build_tenants/common/standards/documentation/README.md)
routes the separate Products; it imports no retired runtime or old proof verdict.
