# Offline proof reader

Implements PR-01–PR-05 with a plain standalone HTML page generated by
`common-tools/proof_reader.py`. It is a sibling of Constraints and Code under
the installed documentation home. The page embeds all reading data and uses
ordinary text DOM nodes; it executes no Lean, subject code or network request.

The fixed documentary subject is the T011 independent full-path report, SHA-256
`8b002e3821e99cd88bae0ccf07794d2e99818ba4e5b38d919fc3e3b45c672061`.
Its eight displayed source members are `AC.lean`, `AC/Audit.lean`,
`AC/Closure.lean`, `AC/Fixture.lean`, `AC/Model.lean`, `AC/Projection.lean`,
`AC/Run.lean` and `AC/Toy.lean`. Each copied byte sequence must match the report.
Changed importer/generator implementations receive no inherited qualification.

The package has eleven members: `index.html`, `PROOFS.json`, `report.json` and
the eight sources under `sources/`. The catalog records source/report identities,
declaration kinds and line ranges, curated claim links and lexical references.
The self-contained HTML also carries the exact source and report text, so it
remains readable when opened alone. Separate source files support direct audit.

The bounded declaration scanner ignores nested comments and string contents,
tracks namespaces, and inventories named declarations in this exact source
profile, including named instances. Anonymous instances and examples close the
preceding declaration and remain available in complete source without fabricated
names in the catalog. Comment-only gaps are excluded from declaration ranges.
It is not a Lean elaborator. References are candidate identifier
occurrences resolved against the displayed source catalog; imported modules
are identified separately. Their labels explicitly say lexical. The generator
does not infer a checked dependency graph from words or imports.

Curated entry points follow the owning a_c source-correspondence table: declared
closure and leastness, complete records, residual preservation, and budget
refusal. A small A→B→C illustration explains the conditional generic result;
it is not presented as an additional executed fixture. Definitions and theorem
statements remain distinct from the retained module/report-level result.

`build --lean-root ROOT --report FILE --output NEW_DIRECTORY` refuses a changed
report or source before output. `check DIRECTORY` validates the exact portable
member set and reproduces both catalog and HTML from copied source/report bytes.
`check_payload(files)` supplies the same check to the documentation packager,
with byte values keyed relative to `proofs/`; it reads no construction workspace.
Missing, extra, symlinked or changed members refuse. Source/report comparison
and renderer reproducibility are documentation checks, not a fresh Lean proof.

Source labels, statements and full files use text nodes. JSON embedded in HTML
escapes delimiter characters. The reader has searchable kind/module filters,
curated examples, statement and proof/source panels, lexical links, Back and
an evidence panel. No result badge is fabricated for individual declarations.

Finite tests cover binding and tamper refusal, declaration names/ranges,
comment/string controls, lexical links, escaping, network independence and
actual offline DOM navigation. Browser visual qualification remains separate.
