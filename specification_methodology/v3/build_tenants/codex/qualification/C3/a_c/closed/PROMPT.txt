## Token state

There are exactly two distinguishable tokens t0 and t1 and two owners A and B.
A complete state assigns exactly one owner to each token. An operation names one
token and destination. Permission is issued by that token's current owner for
that exact token/destination/operation. For the finite executable domain, a
case supplies either no grant, a display label, or one typed grant naming issuer,
token, destination and operation (assign or inspect). The tested operation is
assign. A display label grants no permission.
An unknown current owner observation returns unresolved without an effect.
Known current state plus missing permission returns refused without an effect.
Known current state plus exact permission performs the selected assignment;
only that token can change owner. The token set and single-valued ownership
remain invariant. A later invocation re-observes actual state. None of this
proves universal idempotence or a real distributed transport's recovery.

## Typed join

An edge LengthMetres -> DurationSeconds is incompatible despite equal float
representations. DurationMilliseconds -> DurationSeconds requires the declared
conversion divide by 1000. No source grant follows from a compatible type.

## Finding conservation

An admitted planned set contains exactly slot A, bound to source-v1 and one
producer. Its actual falsified finding cites source/A.md#permission-branch.
Required coverage includes A and B; B is uncovered, not an omitted planned slot.
A conjunction retains that failure, original producer and citation as well as B
uncovered. Its result remains non-green. If A is not supplied/authenticated, a
complete planned-set claim is invalid; no assessment is invented to fill it.

## Authority and interpretation

A predicate result supplies no next-action or acceptance authority. The existing
decision owner chooses a permitted action within its grant. Finite model success,
source fidelity, practical adequacy, mathematical category equivalence, whole
corpus qualification and release are distinct claims. Unknown effects require
observation/reconciliation or an unresolved stop before blind repetition.

"""Exhaust the SOURCE.md token interpretation; not an a_c semantic engine.

The other selected qualitative clauses receive independent source comparison.
This hand-authored executable/model relation also requires that assessment.
"""
import hashlib
import itertools
import json
from pathlib import Path

root = Path(__file__).resolve().parent
if not __debug__:
    raise SystemExit('Finite proof refuses disabled assertions; run without -O/PYTHONOPTIMIZE.')

def operation(owners, token, destination, grant, observed, infer_permission=False):
    if not observed:
        return 'unresolved', owners
    admitted = isinstance(grant, dict) and (
        grant['issuer'] == owners[token] and grant['token'] == token and
        grant['destination'] == destination and grant['operation'] == 'assign')
    label_permission = infer_permission and isinstance(grant, str)
    if not admitted and not label_permission:
        return 'refused', owners
    output = list(owners)
    output[token] = destination
    return 'completed', tuple(output)

grants = [None, 'label:A', 'label:B'] + [
    {'issuer': issuer, 'token': token, 'destination': destination, 'operation': kind}
    for issuer, token, destination, kind in itertools.product(['A', 'B'], range(2), ['A', 'B'], ['assign', 'inspect'])]
counts = {'completed': 0, 'refused': 0, 'unresolved': 0}
violations = []
cases = 0
for owners in itertools.product(['A', 'B'], repeat=2):
    for token, destination, grant, observed in itertools.product(range(2), ['A', 'B'], grants, [False, True]):
        result, output = operation(owners, token, destination, grant, observed)
        assert len(output) == 2 and all(value in {'A', 'B'} for value in output)
        assert output[1-token] == owners[1-token]
        if result == 'completed':
            # Inverse postcondition: every effect has its exact source-owned
            # grant, independently of the implementation's Boolean guard.
            assert grant == {'issuer': owners[token], 'token': token,
                             'destination': destination, 'operation': 'assign'}
            assert observed and output[token] == destination
        else:
            assert output == owners
        if not observed:
            assert result == 'unresolved'
        counts[result] += 1
        bad_result, bad_output = operation(owners, token, destination, grant, observed, True)
        if bad_result != result or bad_output != output:
            violations.append({'owners': list(owners), 'token': token, 'destination': destination,
                               'grant': grant, 'observed': observed,
                               'correct_result': result, 'mutant_result': bad_result,
                               'state_changed_by_mutant': bad_output != output})
        cases += 1
# Independently derived domain cardinalities: 16 exact grants complete; each
# known operation has 18 nonmatching grant values; half the domain is unknown.
assert cases == 608
assert counts == {'completed': 16, 'refused': 288, 'unresolved': 304}
assert len(violations) == 32
harm = next(v for v in violations if v['state_changed_by_mutant'])
assert harm['grant'] in {'label:A', 'label:B'}

first_grant = {'issuer': 'A', 'token': 0, 'destination': 'B', 'operation': 'assign'}
first_result, changed = operation(('A', 'A'), 0, 'B', first_grant, True)
assert first_result == 'completed' and changed == ('B', 'A')
unknown_result, unknown_state = operation(changed, 0, 'B', first_grant, False)
assert unknown_result == 'unresolved' and unknown_state == changed
stale_result, stale_state = operation(changed, 0, 'B', first_grant, True)
assert stale_result == 'refused' and stale_state == changed
current_grant = {'issuer': 'B', 'token': 0, 'destination': 'A', 'operation': 'assign'}
resumed_result, resumed_state = operation(changed, 0, 'A', current_grant, True)
assert resumed_result == 'completed' and resumed_state == ('A', 'A')

# Transformation Library

This non-deciding account groups recurring responsibilities without defining a
new normative hierarchy, specialization or universal instance signature. In a
construction engagement the applicable owner may require purpose, exact subject
and state, interpretation, governing basis, actor capability, inputs, constraints,
permitted effects, output predicate, failures and consumer. Calculus definitions
and other domains retain their own signatures and dependencies. This is neither
a mandatory record schema nor a requirement to add fields to existing records.

These are shared explanatory families. [Spec Method](SPEC_METHOD.md) owns
construction and outcome law; [Frame Method](REFERENCE_FRAME_METHOD.md) owns
reference-frame evaluation and composition. The calculus and domain members
retain their own composition and judgment laws. Domain members determine their admitted outcome and
disposition sets. The library does not supersede those meanings.

## Bind

Recover the current purpose, subject identity, governing specification, role,
authority, state and required relations. Conflicting, missing or stale bindings
are explicit results. A name, path, cached result or available tool is no grant.

## Acquire

Resolve enough authentic material for the selected operation or evaluation.
Declare completeness, freshness, coupled invariants and interpretation. Resolve
references when their bodies are needed. Unavailable evidence, insufficient
context or capability returns pressure for refinement, support, re-entry or a
truthful stop. Acquisition cannot silently drop a governing obligation.

## Transform

Construct output or perform effects within the bound contract. Preserve the
original producer, material inputs and observed effects. Return the instance-owned outcome. A selected Baseline WorkerResult instance
uses candidate_ready/refused/incomplete/re_entry_requested; an AC-013 instance
retains M_b_prime*/hold/gap/refusal. These are domain examples, not a common
mandatory enum. Observe uncertain external effects
before repeating them. The worker's internal search is its HOW; it cannot widen
the outer outcome or effect grant.

## Evaluate

Judge a declared predicate on an exact subject using sufficient admissible
evidence. RF-012's closed base is satisfied, falsified, indeterminate, out_of_frame
or invalid_basis; its externally owned compatible extensions retain the owning
contract's conditions. Preserve original citations and residual coverage.
Other judgment domains retain their admitted result algebras. Where required,
the assessor is independent of authorship. A judgment supplies no repair,
acceptance or next-action authority.

For an UP-020 assessment retain the assessor-disposition field's
evidence classification alongside the predicate result. It can describe that
the cone is preserved, a local realization is defective, an owning relation
needs re-entry or a competing truth path violates the basis. This is assessment
evidence; the decision owner alone performs the authoritative disposition.

## Conjoin

Combine only compatible, authenticated results on a declared common outcome.
Retain each applicable known failure, its producer and citations. Retain required
uncovered coverage separately. For an instance whose admission contract declares
planned assessment slots, authenticate each planned slot; an omitted planned
judgment is handled by that owner's declared admission/result rule; no generic
falsification or rejection is inferred from absence alone. An authenticated set
can still leave a different required responsibility uncovered. The declared
conjunction or decision rule determines the aggregate result. A conjunctive
whole-outcome claim requires every applicable required predicate and seam;
unknown applicability prevents that wider conjunctive satisfaction. A declared
disjunctive rule retains its own semantics. No result may silently erase a
known failure or uncovered responsibility from the evidence it consumed.

## Dispose

The decision owner consumes exact closed work and evaluation results with the
current mandate. For an agentic construction instance it selects accept, local_repair, re_enter
or reject for the declared cone under [UP-020](SPEC_METHOD.md#agentic-construction-execution-stdo-up-020). It may select a next already-authorized action or stop under the instance's
permitted outcomes. Domain-specific yield remains with its declared owner. It cannot change upstream meaning or take a reserved owner decision.
Accept binds an exact checkpoint; it does not imply release. A Product-outcome
acceptance interval is separately governed by
[UP-013](SPEC_METHOD.md#product-outcome-conservation-stdo-up-013).

Other instances retain their own result domains. [Ticket Method](TICKET_METHOD.md)
owns sprint/paydown and work-carrier closure classifications; [Release Method](RELEASE_METHOD.md#successor-baseline-conservation-stdo-up-015)
owns conserved/superseded/intentionally removed/not applicable. An authorized
Writer may record condition-based closure when that owning contract permits it.
Sharing Dispose machinery changes none of those grants or classifications.

Accept requires closure of the declared cone and preservation of every affected
governing relation. Local repair applies when realization or proof is defective
and the governing relation remains coherent. Re-entry applies when Product,
requirement, identity, lifecycle, authority, public contract or accepted design
must change. Reject applies to a violated governing relation or an undisposed
competing truth path. These conditions preserve the evidence classification
without transferring decision authority to an assessor.

## Composition law

[Transformation admission](DESIGN_MODULE_METHOD.md#transformation-admission-completeness-stdo-up-016)
and [bounded-frame conservation](DESIGN_MODULE_METHOD.md#bounded-frame-conservation-stdo-up-017)
own design composition; [Frame Method](REFERENCE_FRAME_METHOD.md#using-frames-in-conjunction)
owns frame conjunction, and [the calculus](AXIOMATIC_CALCULUS.md#ac-016-typed-composition)
owns its typed traversal composition. The account below preserves each owning
contract's restrictions; an explicit translation is lawful only where that
contract admits it.

For T: X -> Y and S: Y -> Z, S after T is admitted only when carried meaning,
identity, basis, lifecycle, effects and authority match or have a lawful explicit
translation. Composition preserves the outer predicate and material invariant
set. A shared helper may implement several instances; differing semantic owners
remain parameters or distinct contracts. Independent judgment cannot be
compressed into author self-assessment.

An identity transformation preserves the selected subject and interpretation;
associative regrouping is valid only when it preserves observable effects,
failure, material context and decision boundaries. This states a bounded
composition obligation, not a universal category theorem for arbitrary software.

## Recovery law

[UP-020](SPEC_METHOD.md#agentic-construction-execution-stdo-up-020) owns the
construction, progress, checkpoint and proof determinations summarized here.
After interruption, bind the same work identity to its observed current state.
Reassess only materially affected premises and retain applicable work. Reconstruct
needed authority and observations from their declared owners, not private memory.
Uncertainty about effects, freshness or evidence remains explicit. Rejected or
superseded construction is churn. Repeating an unchanged failed
relation without a supported causal change is a prohibited retry practice;
it is not the definition of all churn.

Accepted material movement toward the selected Product is progress. Prerequisite
work names the Product obligation it enables. Preservation and repeated proof
are evidence, not new Product progress. Discovered distance revises the forecast;
it is not negative progress. File, event, commit and token volume do not measure
progress. A proposed construction restart identifies why repair is insufficient, what
survives and which causal assumptions change under UP-020. This is distinct from
process resumption over retained current work. Deletion, archival, quarantine
and salvage mechanics remain consumer-owned under UP-013; this summary imposes
no additional discard law. Each actual operation still needs its existing grant.

Use the cheapest focused proof that can falsify the active relation. Whole-
candidate qualification belongs at a declared boundary unless affected risk
requires it earlier. When reconstructability matters, destroy or exclude the
incidental process state and compare reconstructed semantic outcomes; a same-
process check cannot prove durable authority.

## Cost and contraction

[Method proportionality](SPEC_METHOD.md#proportional-method-and-delivery-stdo-up-014)
is ambiguity removed relative to effective reasoning complexity; raw counts alone
cannot establish it. For a computational or handoff cost claim, select those
measures material to that claim. Possible measures include transferred/acquired
bytes, attention, I/O, CPU, addressable memory, critical-path elapsed time,
aggregate work or displaced human assurance. This is an illustrative choice,
not an all-fields obligation, universal quota or separate accounting carrier.

A reference reduces storage only when its resolution preserves adequacy. A
smaller document or faster local preparation does not prove whole-path
improvement. Contract duplicated meaning and authority only while preserving
required distinctions and independent evaluations.

# STDO Foundations

STDO specifies purposeful construction by actors with finite resources. In a
selected construction or evaluation engagement, purpose, subject interpretation,
governing basis, actor and evidence are material bindings under their respective
owners. They are not dependencies of every calculus definition. These foundations
are a non-deciding explanatory account. They introduce no duties, grants or
acceptance conditions beyond the named owning contracts. The explanatory direction abstracts
recurring relations from the detailed owners, then maps instances back to those
exact contracts. It creates no normative hierarchy, derivation provenance or
constitutional specialization relation. [Spec Method](SPEC_METHOD.md)
owns constitutional construction and [Frame Method](REFERENCE_FRAME_METHOD.md)
owns material evaluation context; explanatory consolidation preserves their
source-owned determinations.

## Premises and standing

An actor has finite attention, context, time, storage and capability. This is a
resource premise. It does not choose an outcome, confer authority, identify an
object or prove compatible composition. Those commitments require their own
premises.

A selected purpose U_foundation supplies an adequacy predicate and reserved value choices.
An object O_subject supplies a scoped identity, boundary, current state and material
relations. An interpretation context kappa_interpretation determines the meaning available to
a consumer. A governing specification Sigma_contract declares obligations and admissible
variation. A grant bounds who may act and decide. Observations and arguments
support claims only on their declared subject and basis.

The declared bounded context is `urn:stdo:bounded-context:foundations`.
Its owner is the STDO Specification Methodology Product authority. Its selected
basis is this member's definitions at the exact member digest together with the
cited source-owned clauses, bound under the activation's governing cut. Its scope
is the whole member's explanatory terms, symbols and explicitly scoped hypotheses,
including the account in Orthogonal descriptions. The context identity is stable
across location or permitted representation changes; a new digest still changes
content and may change applicability.

These symbols do not define similarly spelled symbols in method-identity,
traversal, ticket, world-model or calculus contexts.
[Bounded-context resolution](SPEC_METHOD.md#bounded-context-semantic-resolution)
governs cross-context use; no shared default interpretation is inferred.

These premises explain how the source-owned obligations fit together: preserve
the selected outcome and constraints, supply material context, conserve identity
and authority, and report supported outcomes. This is an explanatory account,
not an entailment proof or replacement derivation basis for those laws. Finite
capacity alone does not select the other premises or confer authority.

## Interpretation and representation

A representation is an encoding. An interpretation relates that encoding to
meaning under a declared context. Equal encodings can have different meanings;
different encodings can represent the same scoped meaning. A parser, structural
validator or successful join does not establish interpretation fidelity.

An operational algorithm can make an interpretation testable. Universal claims
that every meaning has an algorithmic encoding require a defined domain,
adequacy relation and argument; they remain hypotheses outside that domain.
For an a_c subject interpretation, the
[calculus fidelity law](AXIOMATIC_CALCULUS.md#ac-017-interpretation-fidelity)
owns that calculus-specific obligation. In reference-frame evaluation,
[RF-007](REFERENCE_FRAME_METHOD.md#rf-007-semantic-evidence-and-verdict-separation)
owns separation of semantics, evidence and verdict. These examples supply no
universal authority for interpretations outside their declared domains. The
governing contract determines admissible loss, abstraction and which consumer
distinctions must remain recoverable; this account supplies no additional loss law.

## Purpose and interfaces

The [Product outcome law](SPEC_METHOD.md#product-outcome-conservation-stdo-up-013)
owns the requiring relation for Product-outcome-bearing work;
[proportional method law](SPEC_METHOD.md#proportional-method-and-delivery-stdo-up-014)
owns justification of method burden. The purpose owner fixes the observable adequate outcome. An interface exists
because a transformation needs to acquire, convey, judge or effect a material
relation. Its obligations derive from that relation and the outer contract.
A convenient signature, existing function or local test cannot invent Product
meaning. An obligation with no requiring purpose or invariant must be justified
or removed by its owner.

## Identity, state and evidence

Identity distinguishes an object within a declared scope. Identity may survive
a rename, relocation, representation change or allowed state transition.
Content equality does not establish identity; unchanged identity does not
establish current content. A digest binds bytes, not all semantic meaning or
permission.

[Identity Method](IDENTITY_METHOD.md) owns governed names and coordinate changes.
Work state is the current subject under construction. An event, assessment or
receipt is evidence of a scoped observation or judgment. Acceptance is an owner
decision. None of these substitutes for another. Historical evidence remains
historical when current premises change. Reuse requires supported applicability,
including identity, basis, freshness and the predicate actually assessed.

## Typed composition and conservation

Relations compose only when their source and destination types, interpretation,
identity, lifecycle, preconditions, authority and effects are compatible. A
handoff conserves the material outer contract and original producer coordinates.
It retains known failures and their citations, required uncovered coverage and
uncertainty. Local success cannot erase a failed or missing material relation.

[Bounded-frame conservation](DESIGN_MODULE_METHOD.md#bounded-frame-conservation-stdo-up-017)
owns the design obligation. Conservation concerns recoverable meaning, not copying bodies. A reference is
sufficient when its authentic owner, exact selector, availability and consumer
resolution preserve the required relation. A digest of unavailable material
does not supply context. Shared machinery may serve several instances while
their semantic owners, responsibility and independence remain distinct.

## Finite capacity and total handling

The [frame laws](REFERENCE_FRAME_METHOD.md#reference-frame-laws) own material
sufficiency and capability; the [totality rule](DESIGN_MODULE_METHOD.md#8-totality-rule)
owns closed design handling. Each activation binds the actor and capability
envelope materially needed by its claim. No universal numeric budget, resource
ledger or measurement gate follows.
Before acting, establish sufficient material context and capability. If the
coupled relation does not fit, the actor reports the misfit. The existing
human configuration authority may select refinement, another actor,
sequencing or lawful compression under RF-014. Any delegation must come from a
separate applicable grant; RF-014 itself supplies none. The actor acts on an already
authorized response, requests the owning decision, or stops with an explicit
unresolved result; capacity supplies no configuration grant. Never replace a difficult
required relation with an easier claim merely to report success.

A total control function has a defined response for every input in its declared
control domain, including unknown external conditions. It need not solve every
world state or guarantee termination of every problem. Deterministic functions
can have a small closed state machine; probabilistic workers can explore more
outcomes while an enclosing finite control algebra handles failure, incomplete
work, refusal, recovery and exhausted authority truthfully.

Process resumption is another iteration over the current work state under
[agentic construction law](SPEC_METHOD.md#agentic-construction-execution-stdo-up-020). Observe the workspace
and affected dependencies, retain applicable progress, then choose a permitted
action. This does not imply every side effect is idempotent. An uncertain effect
must be observed, reconciled or returned unresolved before any repetition that
could duplicate it. General logging supplies observability and audit and may support reconstruction.
An adopted domain may assign stronger standing: within ODD, the bound ABG role
owns runtime truth and event replay; ledger and evidence admission retain the
ABG/product owners declared by ODD. Those duties remain within ODD scope.
Reloading all history is not a generic method requirement.

## Judgment and authority

The [frame authority law](REFERENCE_FRAME_METHOD.md#rf-006-authority-conservation)
owns authority conservation for frame evaluation. Within a_c,
[AC-014](AXIOMATIC_CALCULUS.md#ac-014-judgment-separation) owns its calculus
judgment separation. Where the construction engagement profile is selected,
[the Baseline](STDO_REFERENCE_FRAME_BASELINE.md#complete-engagement-transition)
owns its exact Reviewer/Executive application of the detailed laws. Other
domain judgment and control functions retain their own declared contracts. Definitions, assumptions, observations, candidate judgments and accepted claims
have distinct standing. A judgment binds a predicate, exact subject, basis,
evidence, assessor and any required independence. An authority grant permits
specified operations or decisions. Neither evidence shape nor actor capability
mints a grant. In the selected construction engagement, a Reviewer judges and a decision
owner disposes under its existing grant. Domain control such as ODD next-action
selection remains with its own named function; the explanation appoints none.

Unknown applicability, missing context, incompatible basis and failed predicates
remain observable. Severity grades the supported consequence if a finding manifests. Priority,
disposition, selected action and promotion effect remain distinct; their
assignment follows the applicable mandate. The semantic result remains separate from the authoritative construction
disposition to repair, re-enter, reject or accept.

## Orthogonal descriptions

Keep three accounts distinct. An algorithmic account specifies the selected
transformation. An informational account explains interpreted distinctions and
their preservation. A computational account realizes the operation over a
hardware and I/O architecture, with material resource costs. They are
simultaneous descriptions, not successive SDLC stages.

To assert a category, specify objects, typed arrows, identities and associative
composition. To assert a functor, show identity and composition preservation.
For a proposed categorical model, A names the algorithmic account, I the
interpreted informational account, and C_H the computational realization on a
declared architecture H. They name categories only after the required objects,
arrows and laws have been supplied. For a proposed span A -> I and A -> C_H,
conformance to Sigma_contract, semantic
equivalence and computational equivalence remain different claims. Categorical
equivalence additionally requires the appropriate quasi-inverse and natural
isomorphisms on a stated domain; an analogy or matching result is insufficient.

State sufficiency for a selected decision, statistical Markov properties,
conditional independence, a mathematical Markov category and a runtime monad
are separate claims. The method neither asserts nor rejects them universally.
Their domains, laws and falsifiers must be supplied before using them as proof.

## Canonical transformations

The [transformation library](TRANSFORMATION_LIBRARY.md) describes Bind, Acquire,
Transform, Evaluate, Conjoin and Dispose. Correspondences name existing contracts and owners;
they are not six compulsory stages or six runtime APIs. The detailed method
members determine their domain contracts, which the library describes through
shared families; no authority derives from that description. This candidate's
design tests a proposed additional family against a material distinction the
existing account cannot express. That is a realization choice, not a new law
for every consuming Product.

## Construction and use

The corpus may exceed one actor's capacity. An activation consumes a sufficient
projected reference frame and exact subject, with acquisition paths for required
material. The projection has declared fidelity and scope; it is not a rival
source of authority. Independent evaluation may require overlapping context at
a different capability or evidence altitude.

Product acceptance, universal mathematical truth, operational efficiency and
release each need their own evidence and authority. Foundational explanation
does not transfer authority from a named detailed method owner.
