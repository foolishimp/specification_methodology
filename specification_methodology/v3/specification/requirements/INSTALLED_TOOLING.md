# Installed representation tooling

This is the distribution extension selected by the owner for STDO 3.0.3 under
[T-006](../../.ai-workspace/tickets/active/T-006-STDO-3.0.3-documentation.md).
a_c owns its representation/formal contracts and STDO Skills owns its two host
packages. Distribution neither migrates their bases nor grants execution or
admission authority.

| ID | Required outcome |
|---|---|
| TOOL-01 | An ordinary complete installation carries the selected a_c representation, code-overlay and Lean source tools, both Skills packages and their required runtime/contract files. An exact closed inventory names source identities and dependencies; no supplemental download is required to obtain those sources. |
| TOOL-02 | A user can verify the installed source bundle and explicitly materialize it into an absent external writable directory. Reject traversal, redirected paths, collisions, overlapping output, extra/missing/altered members and unsafe archive types before extraction. Preserve exact source bytes and relative layout. |
| TOOL-03 | Public commands work from the extracted layout and arbitrary current directory. No mutable work record in the originating repository is an executable runtime dependency. Dependencies not shipped, including the selected manager, Graphify/parser environment, Lean/Mathlib/support and host sessions, are explicit. |
| TOOL-04 | Extraction and tool execution leave the installed release unchanged. Mutable toolchain, cache, origin, evidence and project output belong in explicitly selected writable workspaces. No automatic global installation or consumer basis adoption follows. |
| TOOL-05 | Installed qualification exercises the real manager's manifest/install/verify/resolve path, exact extraction, a public representation/code build and reuse, package checks and meaningful negative controls. Each result states its actual dependency environment and proof/semantic limits. |

The documentation home exposes **Constraints**, **Code example**, **Lean proofs**
and **Use the tools**. Readers remain offline; tool execution has its own setup.
Fresh-machine Lean execution, new Skills actual-host qualification, whole-method
representation and owner semantic acceptance remain separate obligations.
