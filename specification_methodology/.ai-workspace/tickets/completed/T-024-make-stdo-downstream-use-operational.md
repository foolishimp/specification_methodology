## Evaluation Criteria

1. One packaged guide covers getting started, requirement iteration,
   construction/testing activation, review, monitoring, and triage.
2. The convention is `stdo help`, `stdo ticket`, `stdo work`, `stdo review`,
   and `stdo status`, mapped to native Claude and Codex skill names.
3. The five workflow skills are byte-shared. Claude's existing full-standard
   refresh remains manual-only over one packaged procedure; Codex exposes the
   five requested workflow verbs and can read exact standards directly.
4. Claude and Codex manifests, both marketplace entrypoints, and all skill
   metadata validate.
5. Read-only help/status/review cannot silently install, ticket, repair,
   reprioritize, dispose, or continue work.
6. Ticket and work bind the successor Ticket Method's proportional carrier
   selection: no automatic durable ticket, no model self-admission, lawful
   same-invocation admission, and durable preservation only where required.
7. The guide distinguishes product-local method cut, qualified Git transport,
   the immutable RC2 predecessor, and the aligned RC3 plugin-containing cut.

## Non-Closure Conditions

- the guide is absent from the plugin payload;
- either host cannot discover a requested workflow, or Claude can auto-load
  refresh;
- generic non-STDO requests trigger the workflow skills;
- mutable source, conversation history, or a moving selector substitutes for
  the exact installed basis;
- Reviewer severity becomes automatic Executive priority or a universal P2
  release gate;
- the plugin version diverges from its containing STDO cut;
- tests establish only text presence without install and trigger behavior;
- one-run work automatically creates a ticket or requires a separate turn after
  its execution contract is admitted; or
- durable obligations can disappear at the end of a run or sprint.
