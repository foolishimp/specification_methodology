# STRATEGY: End-to-end interface integration reference frame

Author: Codex
Date: 2026-09-16T12:25:00Z
Addresses: Contract meaning across design, producer context, implementation, admission and user outcome
Status: Open — proposed reusable frame; not adopted method or consumer authority

## Summary

The frame evaluates whether one declared user outcome remains constructable,
understandable and correctly realized across its complete interface chain.
It examines both sides of each material boundary and their composition. It
applies during design, implementation, integration/UAT and failure diagnosis;
it is not restricted to post-code testing.

Its central question is: **Does every participant receive enough explicit
contract and current context to perform its responsibility, and does the real
path preserve that contract through to the observed outcome?**

This is a refinement and declared conjunction of existing Public Boundary,
Design/Operator/Owner, Integration, End-to-End, User Acceptance and Proof
evaluations. It adds no actor role, orchestration engine, universal review
stage, test runner, event store or independent acceptance authority.

## Proposed frame declaration

Identity: `urn:stdo:proposal:reference-frame:end-to-end-interface-integration:v1`

### Evaluation family

Evaluate the congruence of one outcome's governing meaning, functional
interfaces, participant context, actual exchanges, owned effects, failure
reporting and user-visible result.

Report distinct claims:

1. **Contract sufficiency:** the declared path is constructable and each
   participant can determine its responsibilities from its supplied interface.
2. **Boundary congruence:** actual producers, transformations and consumers
   implement the declared domains, meanings and authority relations.
3. **Path realization:** the exact runnable subject uses that authoritative
   path, including material state and result/projection boundaries.
4. **User usability:** the ordinary human, LLM or software caller obtains the
   selected outcome using only its declared access and information.

Each claim returns `satisfied`, `falsified`, `indeterminate`, `out_of_frame` or
`invalid_basis`. A design-only evaluation does not claim runtime or UAT
satisfaction. A full end-to-end usability claim requires all four, with an
explicit same-basis conjunction and unresolved obligations retained.

### Subject and basis

Bind one Product outcome and its independently stated oracle; complete selected
requirements and accepted design; supported entry and observable exit; actual
participants and callable implementations; contract/schema/policy revisions;
configuration, capabilities and dependencies; exact subject checkpoint; and
the finite case population. Bind the selected installed/deployed artifact when
that is the claim. The observed application workspace remains a separate subject.

For an LLM participant, also bind role, instruction policy, actual supplied
prompt/context, tool access and model/transport configuration material to the
claim. Generic governance or corpus access does not substitute for the
Product-specific interface contract. A clean-room user receives no private
implementation knowledge or fixture assistance.

### Material manifold

Follow the selected outcome across the actual function/composition boundaries,
from supported entry to result and any required fresh observation. At each
material seam resolve the following coordinates from their existing owners:

| Coordinate | Required distinction |
|---|---|
| Meaning and ownership | What each field or message means; its governing source; who constructs, interprets, validates and accepts it |
| Functional contract | Inputs, declared success postconditions, candidate outputs, refusals, consumer preconditions and permitted effects |
| Value and reference domain | Allowed values/identities, units, cardinality, ordering, empty/null/default behavior and explicit translations |
| Lifecycle and time | Proposed versus admitted versus assessed versus completed; current active input versus retained history; validity interval |
| Participant context | What the producer can actually see or compute; which decisions require contextual judgment; which remain reserved to an owner |
| Transport and transformation | Serialization, parsing, mapping, normalization and version compatibility without unowned changes of meaning |
| Mutable subject | Relevant current bytes/state, observation identity, changes since earlier work and which dependent evidence becomes stale |
| Failure and observation | First violated condition, responsible seam, retained successful work, declared continuation/block and truthful user-facing result |

The working record reuses existing sources and adds only missing cross-interface
relations. Material coordinates cannot be omitted because a schema parses or a
component test passes. Non-material dimensions have an explicit scope reason.

### Coordinates and equality

Distinguish Product definition, immutable artifact/install, mutable workspace,
observation, invocation and candidate/result identities. Bind actual callable
selection and configuration, not merely a path or function name.

Equal JSON shape, text, identifiers or output values do not establish equal
meaning, provenance, lifecycle or authority. Any translation identifies its
source and target domains, preserved meaning, accepted loss, governing owner
and refusal conditions. History is not current input merely because its bytes
remain available. Fresh observations do not invalidate unrelated immutable
authority or unaffected accepted work.

### Invariants

1. **One truth per meaning.** The frame locates the owning contract. Schemas,
   prompts, adapters, indexes and tests remain projections or consumers of it.
   A disagreement returns to the owner; observed output does not redefine the
   oracle.
2. **Complete handoff.** For a seam claiming direct successful handoff, the
   producer's success guarantees meet the consumer's preconditions. When an
   interface deliberately emits candidates, candidate validity, admission and
   semantic assessment remain separate declared stages. LLM variability does
   not make every candidate admissible or every refusal an integration defect.
3. **Explicit actor contract.** Every material condition an actor must obey is
   available in its interface or supplied context. Deterministically available
   domains and current coordinates are computed by their existing owner and
   exposed or exactly locatable within the actor's actual capabilities. The
   actor is not required to infer hidden validator logic.
4. **Shared computed facts.** Validation and context projection use the same
   owned relation, through reuse or proven equivalent projections. The model
   judges meaning within that domain; it does not manufacture eligibility,
   authority, admission or completion.
5. **Current-context iteration.** A later operation examines the relevant
   current mutable subject. It distinguishes active inputs, reusable accepted
   results, unassessed candidates and historical context. Correction invalidates
   affected support and preserves unaffected work.
6. **Authoritative execution.** Thin entry/adaptation surfaces reach the
   declared functions and effect owners. No hidden fallback, test-only path,
   state injection, manual repair or substitute can support a real-path claim.
7. **Causal explanation.** Failure evidence identifies the violated relation
   and originating seam, with a bounded field/path, expected domain or basis,
   observed mismatch and evidence locator where available. Later wrappers keep
   that cause identifiable. Sensitive content follows the Product's redaction
   rules. Missing diagnostic detail remains a visible gap, not an invented cause.
8. **Evidence matches the claim.** Transport success, valid shape, admitted
   result, semantic satisfaction, completed operation and user success retain
   distinct meanings. The claimed outcome has independent expected results
   and exact actual-path evidence.

### Authorities

Existing Product, requirement and accepted-design owners define meaning.
Executive or the project's declared equivalent selects the exact evaluation
and disposes its closed result. Worker applies the frame during authorized
construction and self-check; Reviewer independently evaluates the frozen
subject where independence is required. The frame grants neither role nor
mutation authority and does not require another agent for every interface.

Computed facts belong to the existing deterministic owner. Contextual judgments
belong to the declared semantic actor. Reserved rulings remain with their
existing owner and are reused only within their valid scope. Test execution
does not supply Product or human acceptance authority.

### Evidence

Acquire the owning contracts and both real sides of each selected seam; exact
materialized request/context and response; identity/configuration evidence;
validation decisions; effect/observation records; retained work; and the
ordinary caller's observed outcome. Read events or fresh replay where the
Product owns those facilities; pure functions do not acquire a new event
lifecycle because this frame inspects them.

Mechanical cases establish finite relation properties. They disclose any
test double and its boundary. A fixture that directly constructs valid IDs
from validator knowledge proves only its stated mechanical claim.

For an LLM-interface usability claim, perform clean-room LLM UAT using the
ordinary supplied context and permitted tools. Expected outcomes come from
the governing contract before response inspection. Include a sunny case and
the ordinary ambiguity/negative cases material to that scenario. A harness
must not supply hidden interpretations, edit a response into validity or
silently retry it until green. Live-provider usability requires live-provider
evidence; replayed responses support only the narrower declared claim.

### Capability envelope

The evaluating actor understands the Product outcome, functional composition,
reference and lifecycle semantics, actual participant capabilities, evidence
limits and relevant failure diagnosis. It can inspect the selected interfaces
and observe the actual path without changing the reviewed subject. Missing
access or competence is explicit. Required independence binds the subject and
verdict, not a role label.

### Boundary and exclusions

The activation covers one finite outcome chain and its material interaction
population, not the whole repository, all future failures or universal Product
completion. It does not add resilience infrastructure, a universal schema
generator, new controller, routine human approval or a second truth ledger.

An early sunny-day steel thread can supply bounded evidence; it does not imply
all-case integration coverage. Additional assurance follows existing Product
law and the selected work scope. Exhaustive hardening and unrelated frame
expansion do not become prerequisites by this declaration.

### Optional frame relations

Public Boundary/Design/Operator/Owner evaluations supply source-grounded
contract and responsibility facts. Integration supplies actual seam evidence.
End-to-End supplies complete-path evidence. UAT supplies ordinary-user
usability. Proof evaluates whether those observations support the selected
claim. Shared evidence is referenced once; the different judgments remain
explicit. Intentional overlap targets meaning lost between boundaries.

The consuming decision states which closed results are mandatory and how
conflict, unknown basis and residuals are treated. A satisfied component or
transport result cannot discharge a missing semantic, path or UAT result.

### Invalidation and recharting

Re-evaluate affected conclusions when contract meaning, reference domain,
participant/version, actual prompt/context, callable path, configuration,
capability, translation, relevant workspace observation, lifecycle, oracle or
evidence population changes. Preserve exact historical results and unaffected
evidence; do not rerun successful work solely because the actor changes.

Localize the first mismatch before selecting repair: source-contract ambiguity,
missing actor context, wrong producer output, wrong consumer condition,
translation loss, stale input, path substitution or inadequate observation.
Return the smallest lawful owner/re-entry. A new repair or live retry requires
the existing work authority and a separately bounded activation when required.

### Qualification

The following are proposed frame qualification cases, not executed acceptance:

| Case | Expected frame discrimination |
|---|---|
| Empty eligible reference set | The actor can determine the empty-array requirement from ordinary context; a first-stage sunny outcome reaches the actual consumer. Missing explanation falsifies contract sufficiency even when validation correctly refuses. |
| Nonempty eligible input | Valid prior refs remain usable. The frame rejects a universal empty-array workaround and detects omission of an eligible input that changes the claim. |
| Same-response or historical-only link | The actual consumer refuses an ineligible ref under the correct domain, and evidence identifies that domain. An explicit, adequate contract plus a bad response is distinguished from an inadequate contract. |
| Producer/consumer temporal mismatch | Two individually valid carriers refer to different workspace observations or admission states. Equal shape does not make the handoff current or lawful. |
| Meaning-changing translation | Both sides accept the wire shape but disagree on units, default, identity or ordering. A Product-derived outcome oracle exposes the mismatch. |
| Fixture knows hidden rule | A deterministic fixture passes by reproducing validator logic while clean-room use lacks that rule. Mechanical success does not close usability. |
| Successful output through wrong path | A private helper, injected state, manually repaired output or hidden fallback produces the expected value. The actual-path claim is falsified. |
| Changed workspace with reusable work | Relevant changed bytes affect the next context and dependent evidence; unchanged accepted work survives. Historical snapshots do not replace the current subject. |

Cases bind actual subjects, actor envelopes, evidence and independent expected
results at activation. Representative cases exercise this frame's sensitivity;
their count is not a universal test quota or whole-Product coverage claim.

## Compact activation and return

An activation binds: frame identity/revision; exact outcome and oracle; subject,
method and contract basis; supported entry-to-outcome chain; current-workspace
observation; participants and capabilities; available evidence; role and exact
effect grant or read-only scope; required claim conjunction; time bound, stop
and return consumer. Missing material bindings keep the dependent claim open.

Return one short account with:

- the exact subject and exercised path;
- the four claim verdicts and their evidence;
- first mismatch, originating field/seam and downstream symptoms, if any;
- completed work and preserved candidate/accepted material;
- unknowns, untested cases, substitutions and invalidation conditions; and
- recommended owner/re-entry and the existing decision consumer.

No additional ticket, schema or ledger is required when the existing work
carrier already preserves these relations.
