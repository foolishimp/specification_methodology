# Clean-Room Native LLM UAT Cases

Status: authored, not run. This directory contains test contracts and manual
preparation recipes, not fixtures, execution evidence, an accepted model, or a
Product qualification result.

## Subject And Meaning Owner

The suite exercises a real configured LLM using the selected native STDO
Representation skill, compression, map and exact Axiom mechanics to perform
ordinary bounded tasks. It is live sandbox UAT, not an API unit suite, a
methodology quiz, a canned agent transcript, or a simulated passing toolchain.

[STDO Logical Product Use][source] owns the thirteen functions and MC01–MC14
finite examples. Its source standards own the consumed law. This suite imports
their meaning for qualification; it does not establish alternative scenario
law. Changed or disputed meaning returns to that owner.

STDO Representation owns compression, native instructions, visible frame use,
source re-entry and the observed LLM behavior. Axiom Indexer owns its declared
validation, resolution, reference closure, projection and exact join contracts.
An LLM authors semantic axioms; code computes only declared mechanical closure.
A valid map, projection or join does not decide meaning, applicability,
independence, owner acceptance, or completion.

Relevant local contracts are [native frame use][native],
[dogfood verification][dogfood], [basis and identity][identity], the
[tenant boundary][tenant], and [frame-index design][design].
[T-009][ticket] imports the source model and tracks the native work; it does
not supply new STDO law.

The fixture owner supplies domain observations and any declared classifier,
Public serializer or effect-observation procedure. Axiom does not acquire
those capabilities. A finite, transparent manual preparation procedure is
acceptable here; a later live run still needs actual tool-accessible evidence
and real configured LLM use.

If a required subject, host, skill or source cannot be provisioned, record
blocked_preparation and do not run or score it. If a provisioned advertised
skill or tool then fails ordinary discovery/use, retain an executed UAT
failure, unless that refusal is the case's deliberate expected behavior.
Unsupported candidate capability is a visible readiness gap, never a generic
semantic pass.

## Clean-Room Operator Boundary

The operator receives only one extracted task card, a neutral access/effect
envelope, its fixture and the selected native subject. The envelope names the
native skill, arm, exact mounts, ordinary return destination and available
tools. It contains no expected route or suggested conclusion.

Use a fresh process/conversation and isolated workspace for each arm and
attempt. Physically withhold this suite, expected_results.md, other cards,
repository/ancestor access, prior conversations, author rationale, assessor
messages and previous test answers. Do not rely only on an instruction saying
not to read accessible answers. Disable inherited memory and broad search
paths that expose them; record the actual isolation mechanism.

The source model's SCENARIOS.md contains Model Cases And Oracles. It is
assessor-only: do not mount that answer-bearing file in either operator arm.
The custodian extracts neutral domain facts and actual owning source-law
routes without its expected-route prose. Source re-entry reaches the exact
represented standards and relevant owner records, not the hidden case oracle.
Do not rewrite source law to make the fixture pass.

The same subject, ordinary task, domain evidence, authority/effect boundary,
role, output request, host/model configuration, tools and assessor apply to a
paired comparison. Only the context entry differs:

- Direct-source control starts from the exact owning source prose. It does not
  receive expected_results.md or the MC oracle text.
- Map-first starts from the native skill and exact map, selects actual frames,
  and uses logged bounded source re-entry as needed.

Keep arm order and any unavoidable configuration/access differences visible.
A different host or model is a separately identified observation. Codex
evidence does not qualify Claude, or the reverse. Cross-model independence
does not automatically establish semantic proof.

Direct-source control is a comparator, not the sole oracle. Both arms are
assessed against the independently fixed original-source criteria. If a
source ambiguity appears, retain the attempt as indeterminate; adjudicate
the oracle from source outside the operator context, version it, and run a
new attempt. Do not retrofit expected answers to candidate behavior.

## Native Actions And Effects

The map-first trace shows native discovery, exact binding checks, map loading,
LLM-selected frame URIs/purposes/source routes, relevant rule and evidence
recovery, caller-authored ordered sections, exact join invocation and output,
and the bounded task result. A correct unsupported guess without the required
tool use does not pass native-use UAT. Do not force a join or projection after
a deliberate unresolved identity/authority boundary: the trace must show
where reliance stops.

The source arm uses the same task evidence and applicable mechanical tools,
with its lawful source selection visible. Record actual source reads in both
arms. Whole-corpus reading may recover the right answer but does not
demonstrate useful compressed context; report that limitation separately from
semantic correctness. No fixed token/time budget, accounting ledger,
resource-control frame or universal actor count is imposed.

Only complete-update cases use the two currently declared indexes:

- urn:stdo-representation:frame-index:t009:complete-update-worker
- urn:stdo-representation:frame-index:t009:complete-update-reviewer

Their scope and supporting closure come from [the design][design]. Other
cases use actual map frame_refs and explicit source frames, not invented
executable index IDs. If a selected frame is absent, re-enter its owning
source or expose the missing frame; do not borrow the update index by label.
Released RC4 Axiom has no frame-index projection operation. Projection cases
require a separately frozen capable candidate and bounded qualification grant.

UAT-09-A exercises both overlapping update frames, their shared rules and
multi-premise completion in reference-only and materialized views from the
same subject. UAT-09-B changes a required premise; UAT-09-C supplies the stale
source exception; UAT-13-C tests unavailable outcome evidence. Axiom exposes
closure, while the LLM evaluates the supplied facts and independent assessor
checks the original source meaning.

For read-only projection, omit --output: stdout is the output surface.
--output - creates a literal file named "-", not stdout. An output file or
joined-request file needs the case's explicit sandbox write territory.
Read-only Reviewer/diagnostic cases use stdout or an approved host stream,
and have an observable before/after no-effect check. Platform transcript
capture by the custodian is distinct from operator worktree mutation.

Every mutation occurs only in an isolated copy under that case's existing
grant. The card's ordinary request does not grant production, fleet,
publication, installation, release or unrelated work effects. A Worker/Writer
activation is explicit before its granted effect; Executive and Reviewer
roles do not mutate under those labels. Independence is required only by the
case's actual source condition; direct sufficient work acquires no extra
review, owner ruling, ticket or Executive appointment.

## Assessment And Coverage Claims

Each oracle names required observations, prohibited outcomes and exact
source/fixture trace. Assess semantic result, actual tool path and effect
boundary separately. Refusal can pass a negative case while the requested
capability remains unavailable; report both. Distinguish pass, fail,
indeterminate, blocked_preparation and not_run.

Preserve the first failed attempt and any repair/rerun as distinct exact
subjects and records. A later pass does not erase the failure or qualify the
unobserved predecessor. An effect-observation gap is not proof of no effect,
failure, crash, lost rollback storage, changed preimages or revoked grant.
Seek the permitted observation; withhold dependent completion and unsafe
retry without inventing those facts.

Select and record host, arm and projection variants before execution. Both
projection views and both overlapping frames need direct observations for a
claim covering them; a claim covering both supported hosts needs both hosts.
This suite does not require a giant host-by-arm-by-projection Cartesian
matrix. Report the selected coverage and all unobserved combinations plainly.
Live UAT does not close separate installed E2E, integration, unit, release,
Product acceptance or consumer-adoption conditions.
