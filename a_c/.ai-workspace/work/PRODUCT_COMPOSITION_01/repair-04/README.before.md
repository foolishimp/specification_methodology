# Governed composition support: constructed candidate

The owner selected implementation of the reviewed recursive Product composition
proposal. This a_c Worker changed only the granted requirements/Goals, Graphify
design, code, example and tests. No branch, commit, push, installation, released
corpus change or sibling runtime dependency was introduced. The builder remains
exact STDO 2.5.1 RC2; the native consumer remains exact released 3.0.1 RC1.

The selected implementation is [source-freeze-03.json](source-freeze-03.json).
Its production sources are identical to [source-freeze-02.json](source-freeze-02.json);
only the new absent-binding inspection fixture changed.
Its predecessor [source-freeze-01.json](source-freeze-01.json) and failed checks
remain historical evidence. Independent review and owner acceptance are open.

## Implemented path

An optional operator-selected `composition` SourceRef in the trusted startup
policy enables a finite declaration. It binds exact Product edges/contracts,
actor/purpose/route, permitted sources and operations, provenance/exclusions,
exports, and completeness requirements. `composition.inspect {}` reports the
selected scope without dumping denied sources. Policies without this binding
preserve their previous behavior and can inspect `selected: false`.

The same guard runs through ordinary source/model acquisition, Context assembly,
preflight/dispatch, actor-issued late reads, authenticated output readback,
return capture/check and supported review acquisition. Whole protected Context
envelopes and unknown retained carriers refuse. Known source permission checks
apply to both the requester and activated actor. A shared leaf does not merge
the grants of separate selected routes.

Ordinary F_P input can truthfully remain provenance-incomplete: select
`require_complete: false`, `clean_room: false`, `exclude: []`, and
`output.complete: false`. The rendered Context and retained record keep that
unknown standing. This establishes permitted mediated acquisition and Context
availability, not complete ancestry or source-clean free content. Completeness,
exclusion and clean-room policies hold on unresolved ancestry. Known prohibited
or unauthorized sources still refuse in ordinary mode.

Stable actor history retains actual and conservatively possible exposures,
including inline Context authoring influence. Renaming a principal, changing
policy/engagement, revoking a grant or deleting a source does not make an actor
unexposed. Unknown ancestry survives actor delivery, returned output and later
stricter re-entry. Redacted observation/cancellation remains available under its
existing operation grant when content disclosure has become denied.

## Evidence

The source-selected tests are
[test_ac_support_composition.py](../../../build_tenants/graphify/test_env/test_ac_support_composition.py).
They contain 25 public-path cases, including an actual registered actor making a
late CLI source read and a separate actual native closed-return path. Other
cases exercise prohibited/unknown derivation, both export conditions, exact
source selectors and dirty bytes, shared-leaf grants, target/requester differences,
stable actor history, missing delivery receipts, stale dispatch inputs, live
revocation/cancellation, ordinary unknown ancestry and later strict re-entry.
The corpus uses controlled deterministic subprocesses, not LLM qualification.

The first full regression ran 227 tests and reported four failures, all from two
stale hard-coded operation inventories: three principal subcases and the MCP
schema catalog omitted the new additive `composition.inspect`. The expected set
was updated, with real unbound inspection assertions for all three principals.
[checks-01.json](checks-01.json) and [support-suite.log](support-suite.log) retain
the original result. Other implementation/native tests passed that campaign.

The manager's independent fragment review exposed a genuine analogous defect:
the first a_c scanner accepted anchors shown only in code/comments or as escaped
text. Five actual public counterexamples are retained in
[fragment-before-repair.log](fragment-before-repair.log). The repaired local
scanner excludes them while accepting a real HTML anchor. Its source-level
algorithm reuse has exact [custody](fragment-scanner-loan.json), with no runtime
import from the mutable manager.

The Executive/common Writer also identified a real Product-fit gap: the first
Context path required complete author provenance unconditionally. The successor
implements the ordinary/strict distinction described above; both the Context
positive and strict refusals, plus actual dispatch/return and subsequent strict
actor/parent re-entry, pass their focused checks.

The second full run exercised 230 cases. Its sole failing test had three
principal subcases: the newly added inspection fixture incorrectly assumed
that the old read-only policy granted the new operation. The tool correctly
refused it. The corrected fixture first checks that refusal, then explicitly
adds only `composition.inspect` and checks `selected: false` for each role.
[checks-02.json](checks-02.json) and [support-suite-02.log](support-suite-02.log)
preserve this failed test result; no production source changed for its repair.

Final integrated regression and strict typing are recorded in

[typing-03.log](typing-03.log). Their exact exit statuses and source freeze own

All 231 support tests pass with zero skips, including the 25 composition cases;

## Remaining boundaries

The operator declarations and cooperative host are trusted inputs. This is
mediated enforcement, not OS confinement or a detector of concealed external
information. Required host isolation refuses. Generic `work.write`, additional
admission/return evaluation ingress, alternate-Context return comparisons and
unknown raw carriers remain unsupported under composition. Existing unbound
operations keep their contract; native `results.conjoin` remains unsupported.

Protected history is scoped to the selected Product/evidence surface. It is
not a global inventory of a person or model session's knowledge. Other Products,
hosts and inherited prompt contents require truthful external provenance
declarations; ordinary F_P use can retain them as unknown. Reassigning a stable
identity or asserting complete external provenance remains an operator claim.

Prepared-public/missing-delivery cases and whole-actor provenance are retained
conservatively. This work does not establish minimal taint, optimal context,
semantic adequacy, complete a_c conformance, efficiency gain or Product release.
No Graphify carrier-compatibility claim is derived from these support tests;
the representation Writer owns its separate actual upstream trial.
