- **R3 — discharged under the stated host premise.** Lines 108–195 move protection to shared checkpoint acquisition, before manifest/chunks/corpus/upstream reads, including stage, discovery, ordinary assembly, run, and grounding/repair callers. Existing explicit first-selection values must reach that boundary. Existing design already treats checker selection as trusted startup configuration and retains it in the selected run. The successor now explicitly requires that custody and forbids a hosted wrapper from treating an arbitrary request-selected run as trusted. This is an honest, bounded bootstrap exception, not a claim of filesystem isolation or authenticated arbitrary plans.

The actual SourceRef guard remains before both ordinary and absent-Writer returns. Broad registered roots remain usable; the actual protected target or output overlap is what must refuse. Unselected generation and SourceRefs retain their existing behavior without a new Lean/store dependency. The private origin subtree remains reserved before ordinary input retention, including when origin selection is absent on the Lean checking path.

These are still implementation obligations. In particular, a refusal only after reading a protected member would not satisfy R3, and a well-formed caller JSON success must never satisfy R2.

The full public cold path is a separate predecessor: its first full-size run currently remains incomplete at runtime serialization. A future final identity, including the new reuse helper and any selected origin, will require its own complete cold establishment before any full-size reuse claim.
