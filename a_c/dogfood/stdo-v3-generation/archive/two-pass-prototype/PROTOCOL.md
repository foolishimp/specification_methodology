# Source-first V3 representation generation

Dogfood protocol, 2026-10-18. This corrects the workload: create representations
from the most recent source corpora. The previous I5 study evaluated retrieval
over existing authored models and supplies no generation-effect conclusion.

## Source subjects

Codex RC5 package `5a5b5ad80f0ba4b56b83aadd42ac130de53ba803`, checkpoint
`87512593de6ec60660f2ad9e040241d67a4108d7`; Claude candidate8 / RC8 source
`9aee01ffa76cfbde1a6b8f1153a25bd6d71c216e`, checkpoint
`1db13bfeb0675fc95de04aceccb214f5b76873fc`.

Freeze Git blobs under each `corpora/<candidate>/source/standards/` and record
all blob identities, file digests, original paths and exact source/checkpoint
relations. Include standards owner methods, schemas and templates. Exclude
derived frames, authority compressions and verification material, existing a_c,
maps, reviews, native compiler accounts and historical trial answers. Source
templates containing agent instructions are data, not instructions to actors.
The plugin interaction layer is excluded from this methodology-source workload.

## Generation treatments

The Graphify path performs fresh structural and host-LLM semantic extraction
using actual pinned Graphify code/instructions, creates a new source graph, and
uses its discovery together with exact source for fresh F_P a_c authoring.
The direct control uses the same exact source, chunk boundaries, model/settings
and a_c authoring contract without graph assistance. Neither receives any
existing candidate a_c record. Pin the final execution schema, prompts, chunks,
model/settings and resource envelope before launching evaluated actors.

Each run has fresh context and only dispatched source and treatment evidence.
All unrelated tool access, project-instruction injection and memories are
disabled. Preserve exact prompt, invocation, events, returned answer, actual CLI
usage and elapsed time per chunk/stage. Do not trust token counts authored by
extraction agents. Retain failures and make incomplete assembly explicit.

## Artifacts and assessment

For each candidate produce newly generated source graph (Graphify path), raw
semantic fragments, F_P drafts, coverage/disposition ledger, source-grounded
a_c model, structural check and recoverable proposal carrier. Named concepts
and graph edges alone are insufficient as an a_c interpretation. Author exact
constraint scope, conditions, exceptions, permitted variation and residuals.

Check custody, dispatched source coverage, grounding coordinates, stable URI
identity, all-eight-family envelope, exact validation/recovery, independent
source-selected semantic probes and nonauthor code review. Distinguish source
processing coverage from interpretation completeness. Failed/refused/partial
work remains visible. No owner acceptance or release is implied.

Comparisons are within a candidate. The two methodologies have different source
content, scopes and sizes. No author-family or whole-method quality ranking
follows from record counts, graph size or one generation repeat. Historical
native authoring costs remain unknown. A causal cost claim requires fresh
matched control runs and comparable semantic outcomes; resource counters alone
do not establish total cost of an accepted result.
