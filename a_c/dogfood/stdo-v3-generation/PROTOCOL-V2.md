## Active treatments

`graphify-ac` is an a_c-aware source generation workflow:

1. Actual pinned Graphify deterministic source extraction builds a structural
   graph of documents, hierarchy and explicit references, with failed sources
   refusing success.
2. ONE fresh F_P a_c-aware extraction/authoring pass per exact source chunk
   receives source plus a bounded structural Graphify view. It authors concepts,
   constraints, conditions, exceptions, typed relations with explicit governing
   choices, latitude, residuals and source dispositions under the closed contract.
3. The unchanged mechanical adapter/codec validates and materializes the model;
   actual Graphify builds/exports the resulting proposed semantic carrier and
   exact decode checks preservation.

This is a tenant-specific a_c semantic extraction profile. It is not the stock
Graphify generic-concept extraction prompt. F_P lives inside the implementation;
another compiler need not first create its interpretation. Structural links do
not mechanically become normative dependencies or authority.

`direct` receives the same exact chunks and a_c authoring schema/instructions,
with the same model/settings and ONE fresh F_P pass, without Graphify context.
It uses the same adapter and native proposal validation/recovery.

The existing two-pass `graphify` alternative remains runnable for explicit
experiments, but does not supply the active cost comparison. Requiring general
concept extraction followed by a second full-source interpretation would measure
that extra architectural work rather than a necessary Graphify cost.
