# Source-locator recovery addendum

2026-10-18 02:56 UTC, after the first four evaluated drafts and before recovery
or further semantic assessment. This adds a separate mechanical operation;
`PROTOCOL-V2.md`, `EXECUTION-V2.md`, `freeze-v2.json` and their bound authoring
code/assets remain unchanged.

The first Claude Graphify draft preserved words but dropped indentation in a
wrapped quotation. The strict author checker correctly refused it. The direct
draft also failed, initially on an unknown section identity. Both original
failures, full answers, invocation and usage remain evidence, irrespective of
any subsequently supported repair. Both Codex first drafts passed strictly.

The optional F_D recovery operation may change only `quote`, `start_line` and
`end_line` in a grounding entry. It retains the same section identity and
every non-grounding authored JSON value and order. Its search scope is the
same frozen section dispatched to that actor. After collapsing maximal
whitespace runs to a single separator, it requires exactly one equivalent
source occurrence, retaining case, punctuation and token boundaries. It never
deletes separators, rewrites words, changes a section identity or resolves
ambiguous matches. Original strict-valid anchors need no recovery.

Only an otherwise clean, schema-valid CLI draft with complete reported usage
and verified isolation/custody is eligible. An unknown section, ambiguous or
reworded quotation, non-grounding validation error, timeout, missing usage or
isolation failure refuses recovery. The unchanged strict author checker must
pass on the derived answer. A journal binds original and derived answer hashes,
the source/section/chunk, prompt/schema/settings, invocation, result and helper
identity, with the unchanged authored-payload proof. Assembly re-verifies that
chain and the ordinary native and actual Graphify carrier round trips.

Apply exactly the same operation to both treatments. Report strict first-pass
success/failure, supported mechanical recovery and subsequent F_P repair
separately. Mechanical recovery has its own elapsed time; it creates no new
model usage and neither erases the failed attempt nor establishes semantic
fidelity. Unsupported failures may receive a new F_P attempt under the existing
three-attempt ceiling, retaining the new prompt and usage and withholding the
private semantic oracle. Missing eligible chunks still block complete assembly.

The separate coordinator schedules explicitly selected pending chunks through
the unchanged frozen actor functions, rather than fabricating a strict-pass
marker for a mechanically recovered draft. Every enabled F_P call, including a
fresh retry, uses the exact frozen source/treatment author prompt. No repair
envelope or private source-only oracle is disclosed to these actors. A later
feedback-based repair would need its own separately selected prompt/proof
profile; that optional path is not enabled by this coordinator or helper.
