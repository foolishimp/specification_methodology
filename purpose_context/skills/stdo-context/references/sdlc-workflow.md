workflow constraint purpose. Its 40 rules retain ordinary QA, four-cause

complete native installation through its selected manager, then bind its actual

Choose this purpose for a workflow decision, such as whether a verified local

## Continue from recorded work

After your own control intake, resolve the current ticket through its Product
Definition binding, or the other sufficient carrier selected by the governing
law. Construct the next decision context from its admitted scope, authority
links, current evidence, results, residuals and continuation state. Reconcile
that record with the actual workspace. A summary, prompt or context index is a
derived account; it cannot overrule current governing inputs or evidence.

Choose the actual existing `action` value for the work being resumed. Missing
conversation history is not a new operation or proof of drift, failed work or
no effect. The same purpose and facts apply; `reuse_evidence` reflects actual
reliance and `source_changed` reflects actual material change. Neither may be
set false to conceal known applicability. The five continuity rules preserve
their source-owned conditions without extra caller flags.

Acquire only the material relations needed for the next decision. A qualified
reference must preserve the needed subject/basis, standing, provenance,
obligation/version and invalidators, with an accessible target. When a context
capacity is declared, measure the selected input before reading it in the
declared unit and boundary and record the comparison. A renderer byte budget
does not account for unmeasured host context or prove whole-step fit. Follow the
owning capacity route when it does not fit; never cut material obligations to
obtain a delivery.

Before return, the granted Writer records the required step-produced facts,
results, evidence, decisions, withheld closure, residual obligations and next
authorized action on the existing admitted result surface linked to the work
carrier. Owner rulings keep their original wording and scope. An actor without
that write grant returns the exact evidence to its authorized owner; invoking
this purpose creates no write authority.

On resumption, check applicability and invalidators before reusing results,
retain valid progress and assess any partial writes as they stand. Reconcile
uncertain effects before repetition or dependent action, including an effect
whose outcome is `not_effected` but whose end is unestablished. Context loss
resets nothing and requires no full-history replay or renewed unchanged
approval. Native actual-use evidence, separate from mechanical context checks,
must support any claim that a fresh actor followed this continuation correctly.

## Source-led rebuilding

The Product's [SDLC requirements](../../../specification/requirements/SDLC-WORKFLOW.md)
govern the [closure](../../../authoring/sdlc-workflow/SOURCE-CLOSURE.json),
[authored rules](../../../authoring/sdlc-workflow/RULES.json) and purpose.
Each rule ground pins a complete named source section. The generator resolves
its exact line range and refuses a changed deciding section or requirement
until the author re-enters affected meaning and records a new ground pin.
Full owner bytes still bind the corpus, so other owner changes invalidate old
identity even if their rule meaning can be conserved with evidence.

The preserved development subject remains reproducible from the repository root:

```sh
python3 -B purpose_context/scripts/rebuild_sdlc_index.py --source-root specification_methodology/v3/build_tenants/common/standards
python3 -B purpose_context/scripts/rebuild_sdlc_index.py --source-root specification_methodology/v3/build_tenants/common/standards --check
python3 -B purpose_context/scripts/test_sdlc_index.py
```

On a portable copy, supply the explicitly selected source directory; the frozen
`source/standards` can reproduce its own exact subject but cannot establish
freshness against an unseen newer authoring source. The generator emits source
snapshot/manifest, sources, purpose, index, provenance and its catalog entry,
then regenerates the public manifest after all public files. Existing Python
entries stay unchanged. Refresh the consumer dependency pin only after final
public bytes are stable. External review/actual-use records stay outside this
public bundle to avoid a circular identity.

Retain failed predecessors and affected findings. Reuse old evidence only with
a claim-specific applicability argument; do not copy old index/corpus/query
assessment bindings. Before release, rebind to the actual final immutable cut
and its selected source closure. No future release identity is implied here.

For a release-target rebuild, use the separate constructor after the actual
native cut exists. The predecessor source root contains the retained Python
index's exact `standards/` members; their hashes must match its historical pins.
The [current authoring entry point](../../../authoring/README.md) selects the
explicit RC3 declaration, including the retained RC2 W35 correction. The preserved development recipe and RC1 index retain
the original missing acceptance selector for reproducibility; they are not the
corrected current release inputs on their own.
