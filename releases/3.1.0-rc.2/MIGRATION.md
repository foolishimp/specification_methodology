# RC1 to RC2

RC2 repairs missing predecessor conservation at successor acceptance. Existing
method law, result vocabulary, role grants, ordinary workflow and optional
visual scope remain unchanged. Installation and selectors do not silently
adopt the new basis for a consumer.

1. Verify the consumer's current Product Definition, exact native cut and host
   receipt. Retain work/evidence and current invalidators.
2. Acquire RC2 manager, native manifest and companion archive through the
   [native guide](../../specification_methodology/v3/build_tenants/common/plugins/spec/references/GETTING_STARTED.md#new-project).
   Verify public cohort and asset hashes before use.
3. Apply the owning Product's authorized adoption and installer plan to select
   the complete native RC2 cut, matching Purpose Context package and Skills
   bindings. Remove an old host binding only through its owning receipt.
4. Construct context with actual query facts. RC1 assessments retain original
   identities; a supported RC2 assessment must cover the exact new query.
   Otherwise retain authorized trial standing. Selection and byte checking
   do not assess source-semantic completeness.
5. At successor acceptance, identify the exact predecessor and every relevant
   claim disposition. An unresolved disposition withholds its affected claim.
   Qualification, release and ordinary work retain their own conditions.

RC1 remains available by immutable tag and original assets. Existing
unobserved modes and qualification residuals remain; RC2 claims no universal
coverage, task correctness or automatic host pickup.
