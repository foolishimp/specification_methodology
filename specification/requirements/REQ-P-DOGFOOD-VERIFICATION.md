# REQ-P-DOGFOOD-VERIFICATION — Thin Product Usefulness

Family: `REQ-P-DOGFOOD-*`
Status: Active
Category: Verification

Derives from: `../INTENT.md#success-criterion`,
`../PRODUCT.md#dogfood-and-proof-boundary`, and
`REQ-P-NATIVE-FRAME-USE.md`

## Purpose

Determine whether the STDO authoring map and native instructions are useful
enough to release and keep using. The relevant comparison is direct Source STDO
prose versus map-first use with bounded source re-entry. A joined role request
is a use of the same map, not a claimed GTL level.

## Evidence classes

Deterministic evidence includes exact dependency and source bases, program and
map identities, validation decisions, source routes, refusal cases, skill
inventories, ordered join inputs, and request bytes.

Probabilistic evidence includes task correctness, governing-constraint recovery,
useful residuals, source re-entry, role drift, frame choice, omissions, and
agent preference. It characterizes the observed native agent and instructions;
it does not become semantic proof.

## Requirements

**REQ-P-DOGFOOD-001**: Every retained observation shall bind the exact task,
role, source basis, program, map, skill, native target, model/configuration where
observed, initial context boundary, source re-entry, output, and evaluation
criteria.

**REQ-P-DOGFOOD-002**: Direct-prose and map-first comparisons shall preserve the
same material task, workspace evidence, role, output contract, model capability,
and evaluator. Context differences shall remain visible.

**REQ-P-DOGFOOD-003**: The candidate program shall validate with zero
diagnostics under exact Axiom Indexer and reproduce the same logical map from
the same program and bindings.

**REQ-P-DOGFOOD-004**: Negative observations shall force URI, reference,
source-route, grounding, residual re-entry, and ordering failures. Expected
refusal shall not be reported as successful semantic review.

**REQ-P-DOGFOOD-005**: At least one fresh Codex and one fresh Claude agent shall
discover the native skill, begin from the map rather than complete Source STDO,
complete a real bounded task, and record every source re-entry.

**REQ-P-DOGFOOD-006**: At least one Executive observation shall show selected
frame URIs, purposes, and source routes; retain the exact ordered section array;
and reproduce the same joined request bytes on repetition.

**REQ-P-DOGFOOD-007**: Worker and Reviewer observations shall preserve their
different mutation, evidence, stop, independence, and return relations. Native
instructions, not a claimed deterministic packet engine, are the evaluated
mechanism.

**REQ-P-DOGFOOD-008**: Independent source comparison shall identify recovered
constraints, omissions, incorrect claims, false confidence, unresolved
residuals, and unnecessary source loading. It shall retain regressions and not
select only favorable output.

**REQ-P-DOGFOOD-009**: A release hold is mandatory when map-first use is
materially worse than direct Source STDO prose on governing constraints or
source recovery, when a fresh native agent cannot use the skill, or when frame
selection becomes hidden.

**REQ-P-DOGFOOD-010**: A positive result requires evidence that the map is
useful for the selected tasks, preserves material governing constraints and
source recovery, and reduces repeated context reconstruction or frame drift
without a material regression.

**REQ-P-DOGFOOD-011**: Results from one native target or model family shall not
be generalized to another without direct observation. Target-specific
instruction changes shall be evaluated as instruction changes.

**REQ-P-DOGFOOD-012**: Published claims shall depend only on retained or exactly
reacquirable evidence. Provider attestation is optional unless the claim is an
exact provider invocation occurrence.
