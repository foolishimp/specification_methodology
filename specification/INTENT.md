# STDO Representation Intent

## Intent

Compile one exact STDO release, whose authoritative documents collectively
express the **STDO Symbolic Axiomatic Program**, into a compact, traceable
**Programmatic Semantic Index** for an Outcome-Driven Development probabilistic
traversal (`F_P`). The index presents named semantic declarations, typed
relations, and constraints as a machine-addressable graph so an LLM can reason
over a separately supplied workspace with materially lower context, token, and
cost pressure than loading the complete source documents.

The source documents remain semantic authority. The index is their exact-basis
symbolic encoding and navigation surface: it makes identities resolvable,
dependencies traversable, lawful context projections reproducible, and every
represented declaration re-enterable at its source. It is not a frozen-GTL
executable program, a vector-similarity database, a prompt transcript, or a
replacement constitution.

`F_D`, `F_P`, and `F_H` retain their exact Source STDO meanings as the
fundamental deterministic, probabilistic, and human function classes of the ODD
traversal architecture. This project binds those existing identities; it does
not translate them or create same-spelled local alternatives.

## Desired outcomes

- A carrier-independent programmatic-index algebra owned by WHAT rather than by
  GTL, JSON Schema, a serializer, model, prompt, retrieval engine, or tool.
- One reusable immutable index per exact Source STDO and carrier realization;
  an input workspace or individual LLM invocation does not alter that index.
- Preservation of the identities, authorities, bounded contexts, relations,
  constraints, dependencies, and source routes needed for governed reasoning.
- Exact identity- and relation-driven navigation and projection rather than
  approximate semantic-similarity retrieval as a source of governing law.
- An explicit ODD traversal contract for each claimed `F_P` invocation, with
  bounded inputs, target/output, gates, provenance, and stop states supplied by
  the consuming host rather than embedded runtime machinery.
- Executive-selected, role-bound context packets that set finite reference-frame
  configurations for the Executive itself, Workers, and Reviewers while
  preserving their distinct authority, evidence, stop, and return relations.
- Intent-selected least declared graph closures that fit declared LLM context
  budgets without pretending omitted material was supplied or claiming one
  globally unique minimum frame set.
- Measured reductions in bytes, tokens, and estimated consumption cost against
  the exact Source STDO basis.
- Independent HOW realizations, initially GTL and JSON Schema, that expose
  their carrier boundaries without creating a second STDO authority.
- Probabilistic usefulness observations over representative workspaces without
  reclassifying semantic judgment as deterministic computation.
- Durable `F_H` selection evidence recording what Source STDO material was
  considered, retained, omitted, or left uncertain before deterministic
  carrier construction begins.

## Consumer relation

The primary consumer is an LLM bound to Source STDO's exact graph-native ODD
`F_P` function identity. The compact notation is a projection of a complete
external traversal contract:

```text
F_P(programmatic_semantic_index, workspace_input, intent, frame,
    capability_budget)
  -> probabilistic reasoning | hold | gap | refusal
```

The LLM is the bounded probabilistic interpreter of the represented symbolic
axiomatic program. The index constrains and informs that reasoning; the LLM
does not execute a frozen-GTL `GtlProgram`. Consumption does not make the LLM
deterministic, execute STDO, own the workspace, admit runtime truth, or grant
the LLM semantic, decision, operation, acceptance, or closure authority.

Tenant or host domain mechanics own reproducible construction,
canonicalization, serialization, and measurement. `F_D` evaluates or proves
declared deterministic properties of those results. `F_H` owns
semantic-selection, frame-assignment, and Product-acceptance decisions only
under an explicit authority grant. Neither function may substitute for `F_P`
semantic reasoning, and `F_P` may not claim either function's authority.

## Constitutional relation

Source STDO owns every represented meaning and governing relation. This Product
owns only the carrier-independent programmatic-index algebra, consumption
contract, projection law, identity law, and compression obligations. Each build
tenant owns its direct carrier realization and canonical form.

The common algebra is not a serialized intermediate representation. Each tenant
realizes the graph and constraints directly in its selected carrier. A host may
place that carrier in an LLM context alongside a workspace input, but the host,
workspace, prompt assembly, model invocation, and response remain separate
consumer concerns.

An Executive may use the immutable index to select or confirm an exact frame
configuration and derive a proportionate context packet for itself, a Worker,
or a Reviewer. The packet is an invocation input projected from the Product; it
does not mutate the Product, create a new constitution, or grant authority by
visibility.

## Non-goals

- Deterministic semantic assessment of a workspace or an LLM response.
- A complete occurrence census, exactly-once semantic coverage matrix, or
  deterministic `complete` / `limited` / `blocked` semantic disposition.
- Embedding or owning HoG, ABG, a workflow engine, runtime event model,
  continuation mechanism, or runtime-truth carrier inside the programmatic-index
  Product. A consuming Product may bind those realizations externally.
- Prescribing a step-by-step solution procedure, prompt strategy, or hidden
  selection policy for the `F_P` consumer.
- Treating embeddings, vector similarity, or retrieval rank as constitutional
  identity, authority, dependency, inclusion, omission, or closure truth.
- Claiming one universal or globally minimal context packet independent of
  outcome, actor capability, risk, evidence, or frame-set authority.
- Making GTL, JSON Schema, a model, or a generated artifact a second source of
  STDO semantic authority.
- Treating lower byte or token count alone as evidence that the index is
  useful or semantically adequate.
- Inferring cross-context equivalence from equal spelling or similar topology.
