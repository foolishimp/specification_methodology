A release is cut by one command of the product's own, under version control, and it states only what that command read or checked. This ticket repairs seven findings of the review of release 3.2.0, four of severity 3 and three of severity 5. The intent and the product definition are not changed by this ticket.

The rule. One command cuts the whole release, in this order: Builder's own release, as now; the bundle, which holds a release of the method's standards beside it; the download, one compressed file of the bundle; and last, an install from that download, unpacked with every member kept as a file, that ends with the installed product giving its version. Where a step fails the cut fails, names the step, and leaves no download behind. No part of a release is made by a script outside version control, or by hand. Each statement of fact in the bundle's installation page and release note (a version, the release of the standards, a licence, what is put off, what a command prints) is written by the cut from what it has just read or checked. No such statement is typed into the script as a sentence about one release.

The bundle. REQ-INTERFACE-004 says a release of the product "can join a release of the method as one more product" and defines "no other kind of manifest". The bundle's manifest is therefore of the kind Builder's own is: it names a profile of its own, the product, the version, and every file of the bundle but itself as `path`, `bytes` and `sha256`; beside these it names the release of each part with the sha256 of that part's own manifest. It ends with the codes its page lists and no other, and where it fails it leaves nothing it made. The history page is part of a bundle only where the person who cuts gives one for that cut.

The download. It holds the files the bundle's manifest names and the manifest, each as a plain file, and nothing else: no side file for a file's extended attributes, and no name of the person who cut it. Measured on this machine (bsdtar 3.5.3): macOS tar writes a side file `._<name>` for a file that carries an extended attribute, does not show it in its own listing, and folds it away again when it unpacks, so the fault shows only where every member is kept as a file, as on Linux. With COPYFILE_DISABLE=1, `--no-xattrs`, `--uid 0 --gid 0` and empty owner and group names, a plain reader finds only the files, with no name on them.
