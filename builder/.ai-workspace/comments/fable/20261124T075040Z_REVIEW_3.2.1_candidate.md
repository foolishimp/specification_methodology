# No. Review of the 3.2.1 candidate of STDO Builder (build 3.2.1-rc.4): bug report

**Verdict: no.** C-1, G-1, R-1 and R-2 are each repaired as they were found: I saw each go wrong on 3.2.0 and go right on the installed build. The claim fails on two counts. The repair of C-1 has a hole of C-1's own weight (V-1, severity 2): a session that removes the files git ignores, as `git clean -fdx` does, removes the framework's record of the session with them, and what the session changed outside its step is then committed and merged with no ruling; where the run is also interrupted, with no word at all. And the pages of the release as cut say things that are not so (V-2, V-4, V-5, and one sentence under V-1). The only guard rail I found broken is rail 1, in the case of V-1.

Counts: severity 1: none. Severity 2: one. Severity 3: one. Severity 4: two. Severity 5: one.

The *hold* is the file a run keeps while it works on a ticket, under `.stdo-builder/local/holds/`; a hold left behind is how the next run knows that a run was cut off. Git is told to ignore `.stdo-builder/local/`.

## 2. Findings

### V-1. Where a session removes the files git ignores, what it changed outside its step is committed and merged with no ruling; where the run is then interrupted, with no word at all

- **Severity.** 2. The consequence is C-1's, and by the reading the last review gave C-1 it breaks guard rail 1. The case is narrower than C-1's: the session must remove what git ignores in the folder. No intent to get round the framework is needed. `git clean -fdx` is an ordinary command for a clean build, and the packet the framework gives each session says "What the work or its build leaves that is no part of the product, such as compiled output, is listed in the .gitignore". I did not measure how often an agent gives that command.
- **Reviewed.** The installed build. `src/flows/step.ts:315-319`: after a session the kept identities are read again from their file; where the file is gone, the step goes on to its checks and its commit, and says so in one sentence. `src/flows/run.ts:245-251` and `:306-325`: a run knows that an earlier run was cut off only by the hold it left; with no hold and no kept identities, all that is not committed is committed as `what the user changed by hand`. The kept identities, the hold and the event log all lie in `.stdo-builder/local/`, which git ignores, and since ticket W the session works in that same folder.
- **Claim it breaks.** That C-1 is repaired. Ticket P's rule: "What changed while a session worked is named to the user, who rules before anything of the step is judged or committed." REQ-FLOW-005 (`FLOWS.md:648-651`): "Until the user has ruled on what changed while a session worked (REQ-FLOW-006), the framework judges nothing on the ticket, commits nothing on it, starts no session on it and merges nothing". For the interrupted run also REQ-FLOW-003 step 1 (`FLOWS.md:322-326`) and the page, `INSTRUCTIONS.md:226-228`: "Where a run was cut off while its session worked and those identities are missing, the commit the folder is on stands in for them, with nothing counted as what the step writes: each file not committed is put to you"; and REQ-ALG-008 (`ALGORITHMS.md:414-416`): the framework "counts nothing for their lack as the user's change by hand".
  For the session that returns, the code does what one sentence of REQ-ALG-008 says (`ALGORITHMS.md:406`: "Where they are missing, `trespass` says so and returns nothing") and what `INSTRUCTIONS.md:236-238` says ("says it cannot tell what changed while that session worked, and goes on"). There the hole is in the rule: it gives a session that returned less care than one that was cut off.
- **Evidence.** In each trial the session on `write-specification` wrote its three files and also set the command of the check "the tests pass" to `true` in `.stdo-builder/graph.json`, added a line to `AGENTS.md`, and wrote `left-by-a-session.txt`.
  1. The control, `sh E/trials/a1.sh control`: the run ends "The run waits for your ruling on what changed while the session on write-specification worked", naming `left-by-a-session.txt (added)`, `.stdo-builder/graph.json (changed)`, `AGENTS.md (changed)`. Nothing is committed.

After two ordinary yeses: "main holds left-by-a-session.txt", "main's graph runs its command checks as: the tests pass = true", "main's AGENTS.md holds the session's line: 1", "rulings on what changed in the ticket: 0". The same with `git clean -fdx` as the session's first act (`a1.sh cleanx-first "cleanx+fix+graphtrue+agentsmd+own"`). The event log then held 5 lines, the first "session returned": what it held before is gone, and no command said so.
  3. The run is interrupted, `sh E/trials/a4.sh INT`. The session's first act is `git clean -fdx`; it then does the same three things and is still at work when the run gets the interrupt signal, as Ctrl-C gives it. Run 2 exits 130 and prints nothing. Run 3 exits 0 with the ordinary question; the words "cannot tell" are in nothing it prints, and it asks for no ruling. Commit `f862fa5 what the user changed by hand` holds the three changes. After two ordinary yeses the ticket is done: "main holds left-by-a-session.txt", "main's graph runs its command checks as: the tests pass = true", "rulings on what changed in the ticket: 0" (`E/out/a4.INT.then.txt`). `a4.sh KILL` ends the same way (`c4070cf what the user changed by hand`).

## 3. The guard rails

1. *The framework controls the agent.* Tickets S and P make this stronger. It is still broken in the case of V-1, where one command of the agent's makes the framework commit the agent's changes as the user's.
2. *The workspace is never frozen, copied or rebuilt.* No break found. One working tree and no second folder in every trial.
3. *The workspace is the truth, read as it is now.* No break found. The folder's branch is read at each command; the branch a ticket left is written in the ticket.
4. *Everything the agent does, and every proof, is in the workspace.* No break found.
5. *References, never copies.* No break found. The kept identities name a git tree and hold no content.
6. *The log is only added to.* The framework only adds to it. Since ticket W a session's `git clean -fdx` removes it, and the run goes on with a new one, in V-1's item 2 without saying so. Whether that breaks the rail is the owner's to say.
7. *No opinion on how the agent works inside a step.* No break found. Only what differs when the session is over is asked about (the Executive's case `undo`).
