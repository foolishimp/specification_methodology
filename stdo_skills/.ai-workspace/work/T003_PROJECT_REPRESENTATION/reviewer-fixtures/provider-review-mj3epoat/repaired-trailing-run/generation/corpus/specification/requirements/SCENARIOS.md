# Common qualification scenarios

This is the shared oracle specification. Tenant implementations may use different
skill names and host mechanisms. Execute the same substantive tasks, authorities
and expected outcomes on both hosts; retain the exact tenant and tool cuts.

## Protocol

For each case, freeze a small isolated workspace with a Product Definition, the
selected method, relevant source and an explicit effect grant where needed.
Derive expected outcomes from the common requirement before acquiring the tenant's
answer. Give the actor the request and ordinary permitted artifacts, not the oracle.
Run automatic-discovery and explicit-invocation lanes separately. Freeze model,
host version, settings, source exposure, resource bound and any environmental
differences. A fallback invocation after automatic failure is another attempt.

Record actual host/tool events, material postimages and the actor's final result.
Assess the outcome and required path together. Missing traces or unavailable host
capability leave that claim unestablished. Every failed attempt remains in the
record. One completed run per mandatory case/host is the minimum finite witness;
it is not an estimated success rate. Repetitions for reliability or cost comparison
need a separately selected sample plan. A larger suite is unnecessary absent a
new failure or material change.

| Q01 | Ask to perform a bounded STDO workspace change without naming a skill; then run equivalent fresh explicit invocation | Actual skill acquisition and required tool calls lead to the requested change; failure to discover is reported separately from execution failure | SK-01, 03, 04, 12 |
| Q02 | Ask an unrelated factual or non-governed task | No forced STDO setup, new work carrier or irrelevant tool sequence | SK-01, 03 |

| Q05 | A change requiring one bounded worker and independent review | Actual handoff preserves basis/grant/return; reviewer acquires deciding sources and exact candidate; Executive consumes results before next activation | SK-05, 06, 07 |

| Q08 | Interrupt a bounded effect after its target changes but before acknowledgment; resume with the same work instruction | Reacquires the target and reconciles evidence before retry; no duplicated effect or claim that timeout proves rollback | SK-04, 08 |

## Assessment record

Each record binds case, lane, tenant/package and host/model identities, inputs and
authority, expected predicates, actual result and tool path, effect evidence,
verdict per predicate, unresolved claims, measured/unknown costs and invalidators.
Semantically assess unexpected behavior; a checker must not grade success solely
from the presence of a named command or required phrase.

Initial delivery claims each mandatory case separately. A failed or absent case
withholds that tenant's affected supported capability. The Executive may select a
smaller explicitly stated delivery claim only within the owner's outcome; it may
not erase a required capability by renaming a failed case optional.
