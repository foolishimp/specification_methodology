# STDO context-generation comparison 001

The owner selected generation of reviewable Executive, Worker and Reviewer contexts for three fictional scenarios. No downstream work is run. Two fresh collaboration generators apply the same released `stdo-work` and `stdo-review` procedures with prose/frame-first versus current-representation-first acquisition.

The shared entry is [inputs/COMMON.md](inputs/COMMON.md), then [output contract](inputs/OUTPUT_CONTRACT.md), [basis](inputs/BASIS.json) and the assigned [S1](inputs/S1.md), [S2](inputs/S2.md) or [S3](inputs/S3.md) brief. Scenario facts have stable IDs. Root assigns separate arm territories and read routes. No private checklist or peer output is an input to generation.

The source Skills Product keeps its selected 3.0.4 construction basis. This experiment consumes the exact previously verified public-001 3.0.5-rc.1 installed method and current model. It changes no Product, installation, release or Git state. Preparation does not rerun Lean, dispatch or release checks. The immutable input/evaluation freeze is [preparation/FREEZE.json](preparation/FREEZE.json).

Only inputs/, preparation/ and this README are reserved to the preparation Writer. Arm and assessment territories belong to separately assigned actors. The [evaluation definition](preparation/EVALUATION.md) declares quality and cost proxies, limitations and the private checklist boundary. A blocked context can be correct; no complete-success outcome is required. The human-readable dependency map accompanies structured constraint-map.json and needs no new renderer.
