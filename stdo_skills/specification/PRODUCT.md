# STDO Skills

## Product boundary

Identity: `urn:stdo:product-definition:stdo-skills`.
Bounded context: `urn:stdo-skills:bounded-context:agent-method-application`.

This Product supplies host bindings that help Codex and Claude apply an exactly
selected STDO method. The native core workflows own intake, grants, work, review,
continuation, status and recovery. Skills preserves their canonical instructions
and references instead of creating another lifecycle or mutable authority store.

The independent Purpose Context Product owns source binding, reusable indexes,
selection, context compilation, freshness and its canonical authoring skill.
Skills owns only the adapter that verifies the selected dependency and forwards
its public operations. Both host tenants consume that same Product. The explicit
[composition](composition/PRODUCTS.md#purpose-context) binds the relationship;
sharing a checkout alone does not establish it.

Representation Tools is a separately selected optional component for visual
source/project/code exploration. Context use has no visual, registry or Lean
prerequisite. The old Skills-owned engine, registry guides and formal support
routes are retired; earlier implementations survive only in exact history.

## Capabilities and boundaries

Both hosts expose the canonical native core five workflows, with the native
Claude refresh workflow where supplied. At relevant constraint acquisition,
code-build, review, handoff and refresh points they use reusable purpose indexes.
When an index does not match the exact source/method/purpose, the dependency
refuses reuse; authoring a new index is an explicitly scoped follow-on, not an
automatic substitution. Unknown facts and unaudited semantic coverage remain open.

Source-first review derives obligations independently before judging candidate
indexes or implementations. A matching hash, compiled context or passing tool
check does not establish source completeness, semantic correctness or authority.

The default adopted frame basis provides the ordinary SDLC cycle: bounded work,
QA, causal triage, re-entry at the owning layer, verification and a decision to
continue or close. Relevant work, review and refresh routes acquire the declared
SDLC-purpose context. They preserve the current outcome, subject, basis, scope
and decision boundary; a new observation cannot silently expand that contract.
An exact repair is verified by the evidence its claim requires. Unchanged valid
support is reused, and additional independent assessment is conditional on the
selected basis. Required acceptance and release gates remain effective.

The source-backed default is shared method guidance selected by this Product's
frame basis. Consumers bind Product-specific policy choices without having to
recreate shared triage or stopping rules in a local constitution. Skills must
carry these defaults through the actual consumer path and demonstrate bounded
behaviour on the declared scenarios, not merely contain the right words.

The installer creates fresh disposable or explicitly selected workspace bindings
with exact package, method, interpreter and component identities. It verifies and
removes only its receipt-owned roots. It does not mutate global skill directories,
upgrade existing bundles, or rewrite immutable releases.
