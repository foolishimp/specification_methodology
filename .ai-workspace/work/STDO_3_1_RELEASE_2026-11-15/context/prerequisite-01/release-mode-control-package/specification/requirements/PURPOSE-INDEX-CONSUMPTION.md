# Purpose index consumption

Skills must consume the independently owned Purpose Context runtime, catalog and
canonical instructions through an exact public manifest. Both hosts use one
adapter. Skills must not fork the compiler, rule semantics or catalog.

At relevant work, build, review, continuation or refresh points, resolve the
selected Product skill and catalog. Select an existing index only for its declared
source, method and purpose. Bind actual source bytes and supplied task facts;
then consume and check the resulting context through the Product public API.
No matching index is a scoped acquisition/authoring decision, not permission to
reuse a different family or silently weaken the purpose. Keep scope and grants
as caller facts, never inferred tool authority.

For release-targeted index work, resolve the latest owner-selected releasable
method and its exact manifest rather than using the constructor's older basis
as the corpus default. Consumer reuse still requires its actual selected method
to match. An unchanged purpose ID across release entries does not establish that
match. Preserve historical entries for older consumers; final-cut packaging must
refresh source/native bindings and obtain an applicable assessment with justified
evidence reuse, without inventing or relabeling a release.

True, false and unknown applicability remain distinct. Missing facts remain
unresolved; source drift and purpose mismatch withhold reuse. Retain actual
context bytes, selection identity and freshness result. A mechanically valid
index or context with no accepted semantic assessment remains trial-only and
must say so. The owning source remains available for required re-entry.

Independent review derives obligations from source before exposure to the
candidate-produced index/result when the deciding review contract requires it.
Neither this skill nor an index may certify its own source completeness.

The current successor purpose separates what a request authorizes from what a
future candidate actually preserves. Bind those facts to the caller's evidence,
not to desired coverage. A supported assessment for governing method constraints
leaves its retained construction, typing, testing, admission and acceptance
obligations to be performed. Forward the exact external assessment to both
consumption and check; no Skills-authored supported judgment or coverage flag is
created. The owning Product's canonical purpose definitions decide applicability.

## Default SDLC coverage

At a governed work, QA, finding-triage, repair, acceptance/release or drift-refresh
decision, select the Purpose Context family's declared SDLC workflow purpose and
bind the actual decision facts. A code-refactoring purpose cannot substitute for
that family. Missing coverage routes to the selected owning source and remains
explicit; the default flow must remain usable without authoring a new local law.

Keep ordinary incremental QA and named boundary assessment distinct. Preserve
the outcome, scope, exact subject and governing basis when presenting findings.
Reviewer evidence informs the decision owner; severity alone cannot assign
priority, expand work, hold unrelated landing or authorize another review round.
When failure recurs, use causal triage and the correct owning re-entry point.

Repairs retain failing-before/passing-after evidence and applicable suite results.
Use tests to verify a repair where the basis permits; an independent recheck
needs its actual trigger and covers affected obligations. Retain applicable
evidence for unchanged claims. Unknown evidence withholds the dependent claim;
it does not justify either a pass or an unrelated global work stop.

A frozen development source is a distinct explicit context selection with its
own identity, provenance and applicable assessment. It does not change the
installed native method, acquire a release identity or migrate a consumer.
The adapter forwards that selection unchanged through the same public API.
When source, purpose or defaults change, require the owner's rebuild/assessment
disposition before using an affected index; retain demonstrably unaffected work.

Acceptance uses the finite SDLC scenarios in SCENARIOS.md through the actual
Skills adapter and selected default instructions. Index/schema checks alone
cannot establish drift control, review termination or consumer compliance.

## Constitutional work-state and context continuity

The default workflow context must retain the existing TICKETS work-record,
carrier-to-execution and state-authority duties and ACTIVATION context,
restart and reuse duties. These come from the selected constitution. Default
frames, skills and guides project them and own no replacement law.

Bind the current ticket or other sufficient admitted carrier before selecting
task facts. Recover the admitted scope, source/evidence, applicable decisions,
residuals and next authorized action from that record and the actual workspace.
Keep work-state authority distinct from governing law and material evidence.
A summary or prior passing observation cannot overrule contrary current inputs.

Construct context for the actual next decision, using qualified accessible
references and source re-entry. Apply any declared acquisition capacity to its
stated boundary before loading, preserving unmeasured host inputs and unresolved
fit. At the permitted result boundary, retain step-produced facts and continuation
state through the existing actor/result and authorized work-state Writer routes.
Resumption checks invalidators and reconciles uncertain effects before retry;
it neither requires the old conversation nor resets retained valid work.

Use Q15-Q18 to observe this through the actual consuming path. Changed owning
source/default projections require affected index generation, exact assessment
and consumer-pin refresh; earlier corpus/query verdicts are not relabeled.
