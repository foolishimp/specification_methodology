# Purpose Context requirements

| ID | Observable obligation | Deciding negative case |
|---|---|---|
| PC-R01 | Public discovery checks the caller-selected manifest and every declared public member. | Changed catalog, index, schema or runtime bytes refuse under the old pin. |
| PC-R02 | Bind the actual installed method manifest and ordered selected source files; disclose the check scope. | Expected digest text with changed/missing actual manifest or source refuses. |
| PC-R03 | Reuse only exact catalog source, purpose and family matches. | Wrong purpose/method/member order/false family refuses; missing or ill-typed family facts return incomplete. |
| PC-R04 | Reuse an unchanged authored index for independent queries and target projects. | Changing target coordinates cannot rebind corpus identity or trigger authoring. |
| PC-R05 | Preserve authored deciding meaning and exact predecessor identity. | The original P1 port stays byte-identical; a separately named semantic successor individually accounts for changed conditions, permissions, dependencies, grounds and uncertainty without rewriting the predecessor. |
| PC-R06 | Distinguish mechanical validity, assessed coverage and delivered identity. | Self-assessment, empty evidence or material unknown cannot produce a qualified covered claim. |
| PC-R07 | Enforce the caller's whole-context UTF-8 byte budget without truncation. | An insufficient bound produces no partial context directory. |
| PC-R08 | Permit explicit new corpora/purposes through the same preparation, authoring and compilation path. | A non-Python documentation purpose cannot require a representation runtime or Python workload fact. |
| PC-R09 | Keep portable source/index assets independent of machine paths and host aliases. | Materialized public copies and both host symlink routes resolve the same checked runtime. |
| PC-R10 | Preserve experiment boundaries. | Historical P1 task outcomes or processing ledgers cannot certify a new source/purpose/query or all STDO releases. |

The canonical authoring contract and index schema are public runtime resources.
Source-semantic adequacy and task-value hypotheses require their own finite
tests; these requirements do not replace them with checksum or schema checks.

The coverage successor adds these bounded requirements:

| ID | Observable obligation | Deciding negative case |
|---|---|---|
| PC-R11 | Distinguish complete preconstruction method constraints from concrete task admission, verification and acceptance. | A future strict pass or no-delta proof must not be fabricated as a query fact or inferred from context coverage. |
| PC-R12 | Retain the original family's conditional ODD/UX cases. | A catalog filter requiring both profiles false, or missing scope treated as false, cannot complete the family. |
| PC-R13 | A requested mutation, failure-carrier departure or typing escape retains its exact source premise conjunction. | Unknown requested evidence withholds coverage; a false request grants no exception and cannot conceal an already planned departure. |
| PC-R14 | Account for all 51 predecessor gaps with source-backed dispositions and separately assessed exact query bindings. | Merely clearing unknowns, author self-review or an assessment of another query cannot establish supported coverage. |

The selected coverage predicate is finite and source-relative. An index does
not certify every Product-specific relation or absent future implementation;
those task inputs and results remain explicitly required at their own boundary.

The release-target successor adds these selection and conservation obligations:

| ID | Observable obligation | Deciding negative case |
|---|---|---|
| PC-R15 | Author a release-target index against the explicitly selected latest releasable semantic source, independently of the Product construction basis; consume only a caller's exact selected basis. | An older constructor pin cannot silently select stale target law; a newer catalog entry cannot migrate an older consumer. |
| PC-R16 | At packaging, reconcile source closure and index bindings to the actual final native cut and preserve only demonstrably applicable prior evidence. | A future version label, stale source/member pin or an assessment bound to a predecessor index/corpus is refused as support for the new subject. |

The [method-target policy](../../skills/stdo-context/references/method-targets.md)
keeps authoring, consumption and final packaging selections distinct. These
requirements do not create a new release gate for unrelated work or mandate
rerunning unaffected evidence merely because a version string changed.

The [SDLC workflow requirements](SDLC-WORKFLOW.md) govern the separate reusable
workflow purpose, source closure, reproducible rebuilding, invalidation and
claim-specific evidence reuse. They are requirements on this Product, not a
new runtime engine or blanket acceptance policy for consumers.
