# Visual project documentation

Use the installed sibling `stdo-context` adapter to invoke the separately selected
visual Product. For task/code-build constraints, follow that sibling skill instead.
The native `stdo-work` workflow retains intake, grant and handoff ownership.

Run `python3 -B <stdo-context>/scripts/provider.py visual -- --help` to verify the
selected visual manifest and inspect the actual public interface. Each operation
is forwarded unchanged; no stale historical profile or formal guide is required.
For direct source use, pass an explicit `--configuration` before `visual`, pointing
to the selected Skills dependency configuration. An unavailable visual component
withholds only visual operations; do not substitute another provider silently.

For a new or resumed source representation, read [project](references/project.md).
For source-to-code/test tracing, read [code](references/code.md). For an existing
model, open its selected explorer and source links. Return actual artifact paths,
source identities, checks and unresolved claims. Visual structure does not prove
source fidelity, implementation correctness or acceptance.
