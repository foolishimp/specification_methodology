# RC3 boundary qualification scenarios

These are explicitly declared hypothetical context-coverage cases for the exact
RC3 native basis in stdo_trial.json. They perform no actual Product acceptance,
release or code change. RC2 is the immutable predecessor when successor
conservation is applicable; the current release record supplies its exact identity.

Acceptance, qualification and release select their own boundary predicate and
required review/reuse/conservation constraints. Ordinary work is not a boundary.
Missing/null/ill-typed boundary values retain unknown applicability. A triage case
has a finding present and an affected source, exercising classification and owner
re-entry without supplying a diagnosis, authority change or future verification.
The index must retain the named classes, Product intended end state and current
Goals epics, rather than accepting a class label as a successful no-drift result.

All claims here are predecision governing-constraint coverage. Actual grants,
Product evidence, independence and acceptance remain separately required.
