# Explicit Product dependencies

## Purpose Context

Required independent Product: `urn:stdo:product-definition:purpose-context`, located
by `purpose_context/stdo_purpose_context.json` in this checkout. It owns reusable
purpose indexes, canonical authoring instructions and context construction.
[DEPENDENCIES.json](DEPENDENCIES.json) pins its PUBLIC_MANIFEST.json and every
transitively enumerated public member. Skills consumes its public CLI unchanged.
The source root may be relocated only with an explicitly supplied root whose exact
manifest and members still match. No implicit sibling-source substitution occurs.

## Optional visual documentation

Optional independent Product: `urn:stdo:product-definition:a-c-implementations`
(Representation Tools), located by `a_c/stdo_a_c.json`. Its separate public manifest
pins only the retained visual runtime. Explicit `--visual-root` selection enables
project/model/code exploration. It is absent from a context-only installation.
The adapter does not establish Graphify extraction prerequisites or claim browser
rendering merely by checking an inventory. No Lean component is consumed.

## Native method and history

The selected installed STDO method owns core workflow instructions. Its exact
manifest and canonical plugin are checked independently of both components.
The selected Skills package inventory, native method manifest and two public component
manifests are distinct identities. Historical five-Product release packages retain
their own original tools/receipts; current source does not rewrite or remove them.
