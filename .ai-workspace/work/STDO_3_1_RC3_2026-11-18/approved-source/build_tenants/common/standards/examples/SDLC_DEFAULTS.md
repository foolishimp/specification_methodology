# SDLC default cases

These cases illustrate the selected [default guidance](../SDLC_DEFAULTS.md).
Each assumes an exact admitted grant and adopted basis. They are examples,
not new law, Product policy or actual-use evidence.

| Situation and observation | Bounded route and verification | Stopping boundary |
|---|---|---|
| A parser rejects a supported value; its unchanged requirement and design decide the answer. A regression reproduces the rejection. | The sufficient Writer repairs the realised surface under the existing grant, runs failing-before/passing-after evidence and the declared suite, and checks upstream truth stayed unchanged. No applicable independent-review trigger is present. | Close that repair on its satisfied conditions. No extra ticket, coordinator or review is created by the fix alone; Product release remains a separate claim. |
| Repeated local patches cannot satisfy two contradictory governing requirements. | Preserve the failed observations, distinguish contradiction from implementation error, and re-enter the requirement owner. Admit a reconciled requirement before deriving design, code and tests. | Return the causal result and required owner decision; do not change requirements merely to turn tests green. |
| A throughput model predicts a bound that measured workloads falsify, although implementation follows accepted design. | Re-enter the predictive model owner with workload, observation, prediction and error. Evaluate the changed model's dependent sizing/design claims. | Withhold the failed prediction; a successful code test does not validate the model. |
| A timeout report has no observation distinguishing server failure from lost response. | Acquire admissible trace/reconciliation evidence under the existing grant; uncertain external completion is reconciled before retry. | If evidence is unavailable, return `indeterminate` with the missing observation. Do not infer either success or a code defect. |
| A review repeatedly grows its context and cannot decide an integration question. | Check exact frame family, subject/basis, capability and evidence first. Bind a smaller sufficient evaluation or a capable specialist and the required interaction conjunction. | Return the capability/coverage gap when it cannot be resolved within the activation. A new role name is not additional evidence. |
| A local QA pass is green but the candidate is now offered for a named release whose basis requires independent installed-path assessment. | Bind that release claim, population, exact candidate and independent source-first Reviewer. Reuse valid mechanics; evaluate the required boundary and judgment. | Local QA does not close release. Missing installed evidence remains an explicit residual. |
| A repair changes a material source capture and has green tests; earlier review covered only half its declared population. | Apply the selected recheck triggers for capture fidelity and incomplete coverage. One bounded independent assessment covers the affected fixes and remaining claim, with a declared conjunction if partitioned. | Tests do not close the dependent claim before required recheck. Budget exhaustion returns uncovered scope, not success. |
| A Reviewer finds an unrelated formatting issue beside a satisfied behavioral claim. | Preserve the observation separately, with its actual relevance and owner. Keep technical severity separate from priority and boundary effect; use authorized carrier mutation only where needed. | The observation does not expand the current grant or create another review round. |
| An owner asks a bug fix to support a new input family and another Product. | Classify the changed outcome and Product boundary, re-enter their owners, and reprice downstream requirements/design/evidence and release scope. | The old ticket or instruction does not authorize the new scope. Hold dependent effects until the owning grant covers them. |
| A later finding contradicts one assumption after a repair was closed; an unrelated calculation's evidence remains valid. | Record the new observation, invalidate the affected claim and dependent uses, retain demonstrably independent support, and select a new bounded disposition. | No automatic full-history re-review. The new disposition binds its own claim and stop condition. |
| A new actor receives a ticket and a summary saying all work is complete; the ticket retains an open obligation and current evidence contradicts one prior result. | Resolve the ticket's exact grant and result/evidence references, acquire the deciding owners and current affected subject, correct the summary, reopen the contradicted support and retain unrelated valid evidence. | Return the remaining obligation and next authorized action through the ticket's named result surface. A session change supplies neither acceptance nor a reset. |
| A resumed ticket records a timed-out external operation but no established completion. | Acquire current effect evidence and reconcile it before any retry or dependent action. Keep completion unknown when the available evidence cannot decide it. | Reconcile, yield or stop within the grant; missing conversation history proves neither success nor absence of an effect. |
| A relevant context exceeds the selected actor's declared capacity while its ticket still covers the work. | Preserve the ticket and obligations; refine or sequence sufficient contexts, use a lawful qualified reference, or return the capability gap through its owner. Measure the declared boundary before acquisition and retain any unmeasured complete-fit limit. | Do not silently omit material obligations, invent a fit result or create another ticket merely for the context boundary. |
| A permitted Reviewer can read a ticket but has no ticket-write grant; a run-scoped task has its own sufficient result surface. | Return the closed result through the granted surface to the permitted Writer; retain the run carrier where its lifetime suffices. | Neither ticket presence nor useful continuity authorizes a ticket edit, a redundant durable ticket or a new Executive mandate. |

For a real trial, fix expectations from the governing sources before candidate
exposure, retain the exact input/output and actor limits, and distinguish the
observed result from the expected result above. Successful wording lookup,
schema validation or a template copy alone establishes no behavioral coverage.
