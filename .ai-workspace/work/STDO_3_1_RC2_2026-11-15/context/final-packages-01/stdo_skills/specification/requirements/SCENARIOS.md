# Finite scenarios and claim boundaries

Freeze exact package/dependencies, nominated Product and method, purpose/query,
source and destination before each observation. Record actual operations, output,
return code, effects and refused/unperformed checks. Local command tests do not
establish automatic host pickup. Source-first agent checks and native host tests
are distinct treatments; historical scenarios are not rerun by source proximity.

| Case | Required observation |
|---|---|
| Q01 Context-only fresh install | Codex and Claude workspace installs verify without a visual component or Lean. Native core frontmatter/references remain bound to the selected installed method. |
| Q02 Existing index use | Installed adapter resolves the independent Product, binds actual selected sources, selects a matching existing index, consumes context and checks it without new index authoring. |
| Q03 Source/purpose/unknown controls | Changed source and wrong purpose refuse reuse; missing deciding fact remains unknown/incomplete rather than silently true or covered. |
| Q04 Ownership and update boundary | Exact receipt verifies/removes owned roots only; altered owned bytes/broadened roots refuse; unrelated files survive. Existing historical installs are not silently migrated. |
| Q05 Optional visual | Explicit visual selection exposes the actual public visual path without Lean; no visual selection leaves context fully usable. |
| Q06 Host pickup | Separately observe automatic discovery and explicit skill invocation in actual Codex and Claude host sessions; command execution alone leaves this unestablished. |
| Q07 Native workflow | Actual intake, direct Writer, coordinated handoff/review, continuation after drift, interrupted effects and truthful status follow the native workflow and current authority. Wrapper inspection alone leaves behavioral qualification open. |
| Q08 Semantic value | Source-first independent assessment checks real deciding obligations, omissions and false additions on a declared workload; schema/identity checks do not establish general coverage or value. |
| Q09 Ordinary QA and repair | An authorized bounded candidate may land while selected QA runs; a reproduced repair closes by applicable evidence without an invented full review or release gate. |
| Q10 Recurring failure and drift | Evidence of a governing requirement/design/model/observation problem reaches its actual owner; changed outcome, scope, basis or assumptions are triaged before dependent action. Recurrence alone proves no particular cause. |
| Q11 Real acceptance boundary | A runnable Product/user-outcome claim retains its required acceptance evidence; local tests or a closed QA item cannot silently satisfy that boundary. |
| Q12 Unrelated findings | Preserve an out-of-claim observation and route it to its owner without automatically expanding or reopening the current claim; an actual shared dependency can invalidate affected reliance. |
| Q13 Incomplete evidence | Unknown material applicability or missing evidence leaves the dependent result unresolved and preserves unrelated authorized progress; no invented pass or blanket stop. |
| Q14 Reuse and stopping | Unchanged valid obligations retain their evidence. Only materially affected claims are reopened and independent rechecks have selected triggers; role changes and later findings alone do not restart full review. |
| Q15 Ticket-led continuation | A recipient without the prior conversation reconstructs the next authorized step from the current ticket/contract, actual workspace and linked evidence; it retains valid completed work and records its exact result through the permitted route. |
| Q16 Contrary retained account | A stale summary or ticket claim cannot overrule governing source or contrary current evidence. Reconcile through the authorized owner, reopen affected support and preserve unaffected work instead of restarting everything. |
| Q17 Unknown effect on resumption | Reacquire authorized effect observations before retry/dependent work. An inconclusive observation retains uncertainty and the required next owner/action; missing private context supplies no absent-effect proof. |
| Q18 Bounded context and sufficient carrier | For an admitted one-run task, use the permitted run carrier without inventing a durable ticket. Where a context capacity is declared, measure its selected acquisition boundary before reading, retain qualified references and explicit unmeasured host inputs, and refuse or lawfully refine overflow instead of clipping. |

Q09-Q18 use realistic inputs with expectations derived independently from owning
source before candidate context acquisition. Retain each actual request, selected
instructions/context identity, consumer response and assessment. Test related
cases in one bounded batch and reuse applicable support. A result applies only
to the observed actor, inputs, source and consumer path; it is not proof of general
effectiveness or automatic host triggering.

No single passing total hides an unperformed case. Report finite cases and limits,
not general reliability, complete corpus coverage or successor release readiness.
