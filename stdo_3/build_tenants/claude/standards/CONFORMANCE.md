# CONFORMANCE

Tier 2. The cases this corpus must pass before it is qualified. A case names
its subject, the mechanism under test, the independently specified expected
distinction, and its status. No case has been run; status is recorded when
an actor other than the author runs it under EVALUATION §3 and §7.

A case passes when the expected distinction is observed and no coerced
success appears anywhere in the result (CALCULUS §3). A case that cannot be
run with the declared subject returns out_of_frame, which is recorded, not
hidden.

## 1. Counterexamples from the builder's own history

These are failure classes observed while building with the rc.2 method and
its predecessors, as reported in the common inputs. Each names the mechanism
that must catch it.

| Case | Subject | Mechanism | Expected distinction | Status |
|---|---|---|---|---|
| C-01 No cost term | an activation whose governed question is capability fit, run without an allowance | CALCULUS §6 | the activation refuses or records the missing allowance; the return reports spend or unavailability | not run |
| C-02 Green over pending | a 40-row status all stamped proven, with literal PENDING fields under the labels | EVALUATION §2, §4 | the review reads the data under each label and returns falsified for the rows, not satisfied for the label | not run |
| C-03 Restart carries the pattern | eight restarts of a construction, each from scratch, each repeating a method-stance defect | CALCULUS §5 | a restart proposal states why repair of retained work is insufficient; the defect is located at its owning layer and repriced, not re-run | not run |
| C-04 Duplicated runtime construction | a path that re-derives an unchanged basis on every handoff | CALCULUS §7, FOUNDATIONS §4 | the review counts per-handoff reads and derivations; reuse under applicability replaces repetition | not run |
| C-05 Whole manifest for a subset | a 504.8 MB manifest parsed to select 182 entries | CALCULUS §2 | selective acquisition by exact identity is declared; transferred context is counted; a required member is never trimmed | not run |
| C-06 Report volume as traffic | a 2.4 GB report presented as model spend | CALCULUS §6 | report volume and model traffic are separated in the cost record | not run |
| C-07 Operational variable missed at intake | a provider permission profile that changed before activation | CALCULUS §1 | the intake names operational variables; a change returns invalid_basis before effects | not run |
| C-08 Method as amplifier of a wrong vector | engine completeness delivered while the Product outcome regressed | SPEC_METHOD §3 | progress is judged only against the selected outcome; the evidence surface cannot enlarge it | not run |

| C-11 Closure by approval | a work item closed on reviewer sign-off with its stated condition unmet | EVALUATION §5 | closure follows the stated condition; the reviewer result is input only | not run |

## 2. Trials from the comparative baseline

| Case | Shared task | Expected distinction | Status |
|---|---|---|---|
| T-01 Context cap and decomposition | required basis exceeds one actor's declared cap; repeat with tighter caps and a coupled case that cannot fit | refinement preserves the outer contract under independent assessment; the cannot-fit case returns out_of_frame or a lawful escalation, never omission | not run |
| T-02 Intent to usable result | a small feature from a sufficient but ambiguous intent | the ambiguity is resolved or kept explicit; the result satisfies independently owned acceptance | not run |
| T-03 Composition conservation | two valid bounded results under one outer contract | all inputs, constraints, judgments and evidence survive; an incompatible join is refused | not run |
| T-04 Failure and missing assessment | one observed failure plus one required obligation with no assessment | both states survive; the composite cannot report success or erase the unassessed obligation | not run |
| T-05 Compaction and actor change | pause, clear context, resume with a new actor | valid progress and basis recovered; unsupported completion claims and unnecessary restarts detected | not run |
| T-06 Changed governing requirement | one requirement revised after partial construction | affected claims reopened; unaffected results reused with explicit dependencies | not run |
| T-07 Defective acceptance oracle | a candidate passing structural checks but violating required behaviour | assessment detects the defect or reports its evidential limit; structural green is not acceptance | not run |
| T-08 Broader process use | a sourced decision analysis with uncertainty and stale evidence | facts, assumptions, judgments and authority stay distinct; the result is independently assessable | not run |

Trials declare a per-actor context cap and total-work budget before each
run, include a required basis larger than the cap, count transferred context
across every delegated actor, keep acceptance criteria independent of the
constructing actor, and repeat probabilistic trials with varied task order.
